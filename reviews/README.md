# レビューの進め方

正式リリース(v1.0.0)の前に、4つの段階でレビューと修正を行います。
レビュー表は **Googleドライブのスプレッドシート** で管理します(このフォルダの `review-sheet.csv` は、最初に取り込むためのひな形です)。

## 段階と流れ

| 段階 | レビューする人 | 見る版 | 修正後の版 |
|---|---|---|---|
| ① AI一次レビュー | Claude・ChatGPT・Gemini(同じページを3つ同時に) | v0.1.0 | v0.2.0 |
| ② 本人レビュー | 本人 | v0.2.0 | v0.3.0 |
| ③ AI最終チェック | Claude・ChatGPT・Gemini | v0.3.0 | v0.4.0 |
| ④ 本人最終レビュー | 本人 | v0.4.0 | **v1.0.0(完全FIX・正式リリース)** |

1. レビューする人は、GitHub Pagesの公開URLでページを見て、表の自分の列に指摘を書く。
2. ①③の段階では、3つのAIの指摘をClaude Codeが読み比べて「総括(採用する修正)」にまとめ、採用しない指摘は「見送った指摘と理由」に書く。
3. Claude Codeが修正し、「Claude Codeの対応内容」「対応バージョン」を埋める。状態を「対応済み」にする。
4. 全ページが「対応済み」か「指摘なし」になったら、版のタグを付けて次の段階へ進む。

## レビュー表の使い方(Googleスプレッドシート)

1. `review-sheet.csv` をGoogleドライブにアップロードし、「Googleスプレッドシートで開く」で変換する(以後はスプレッドシートが正本)。
2. おすすめの設定: 1行目を固定、指摘の列は「折り返す」、「状態」の列にプルダウン(データの入力規則)を設定する。
3. 「状態」の値: `未着手` / `レビュー済み` / `対応中` / `対応済み` / `指摘なし` / `見送り`
4. 1行は「1ページ × 1段階」です。「段階」の列で絞り込むと、今の段階の行だけを表示できます。「サイト全体」の行には、全ページに共通する指摘(用語の統一・デザインなど)を書きます。

## Claude Codeへの渡し方

Claude CodeはGoogleドライブを直接編集できないため、次のどちらかでやり取りします。

- **読む**: スプレッドシートを「リンクを知っている全員が閲覧可」にしてURLを伝える(Claude CodeがCSVとして読み込む)。または、スプレッドシートを「ファイル → ダウンロード → CSV」で保存し、`reviews/inbox/` に置く(このフォルダはGitに入れない)。
- **書く**: Claude Codeは「総括」「見送った指摘と理由」「対応内容」「対応バージョン」「状態」の列を埋めたCSVを `reviews/inbox/` に出力するので、その列をスプレッドシートに貼り戻す。

## AIへのレビュー依頼文(ひな形)

ChatGPT・Gemini・Claude(チャット)に、同じ依頼文を送ります。`{ページ名}` と `{URL}` を差し替えてください。

```
次のWebページをレビューしてください。
デザインシステム比較サイト「DesignSystem Port」の1ページで、Apple(HIG)・Google(Material Design)・W3C(WCAG)・Nielsen Norman Groupの指針を比較し、AIの統合見解(AI解釈)を載せています。

ページ: {ページ名}
URL: {URL}

次の観点で、問題がある箇所だけを具体的に挙げてください(問題がなければ「指摘なし」)。
1. 事実の誤り(数値・基準番号・公式の記述との食い違い)。可能なら公式ページで確認した根拠を添える
2. 公式リンクの誤り・リンク切れ
3. 分かりにくい表現・専門用語の説明不足(読み手はデザイナー・エンジニア)
4. 他のページや同じページ内での矛盾・表記ゆれ
5. 図や表の見にくさ・表示崩れ(PCとスマートフォンの両方)
6. 抜けている重要な観点

回答は「観点番号/該当箇所/問題/修正案」の形の箇条書きでお願いします。
```

## 版(バージョン)の付け方

- 段階の修正を終えるごとに、マイナー番号を上げる(v0.2.0 → v0.3.0 …)。
- 段階の途中の小さな修正は、パッチ番号を上げる(v0.2.1 …)。
- 版ごとの変更内容は、リポジトリ直下の `CHANGELOG.md` とGitHubのReleasesに書く。
