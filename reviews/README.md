# レビューの進め方

正式リリース(v1.0.0)の前に、AIと本人によるレビューと修正を繰り返します(全10ステップ)。
レビュー表は **Googleドライブのスプレッドシート** で管理します(このフォルダの `review-sheet.csv` は、最初に取り込むためのひな形です)。

## ステップと流れ

レビューは「1回目」「2回目」「最終」の3回で、AIのレビューと本人のレビューを交互に行い、そのたびにClaude Codeが修正します。

| ステップ | 誰が | 見る版 | 修正後の版 | シート |
|---|---|---|---|---|
| ① AIレビュー(1回目) | Claude・ChatGPT・Gemini(同じページを3つ同時に) | v0.1.0 | | 1回目レビュー表 |
| ② 修正 | Claude Code(3つの指摘を総括して修正) | | v0.2.0 | 1回目レビュー表 |
| ③ 本人レビュー(1回目) | 本人 | v0.2.0 | | 1回目レビュー表 |
| ④ 修正 | Claude Code | | v0.3.0 | 1回目レビュー表 |
| ⑤ AIレビュー(2回目) | Claude・ChatGPT・Gemini | v0.3.0 | | 2回目レビュー表 |
| ⑥ 修正 | Claude Code | | v0.4.0 | 2回目レビュー表 |
| ⑦ 本人レビュー(2回目) | 本人 | v0.4.0 | | 2回目レビュー表 |
| ⑧ 修正 | Claude Code | | v0.5.0 | 2回目レビュー表 |
| ⑨ AI最終チェック | Claude・ChatGPT・Gemini | v0.5.0 | 修正があればv0.6.0 | 最終レビュー |
| ⑩ 本人最終レビュー | 本人 | 最新版 | **v1.0.0(完全FIX・正式リリース)** | 最終レビュー |

- AIのレビューの後は、Claude Codeが3つのAIの指摘を一次情報で確かめて読み比べ、「総括(採用する修正)」にまとめ、採用しない指摘は「見送った指摘と理由」に書いてから修正する。
- 修正したら「対応内容」「対応バージョン」を埋め、状態を「対応済み」にする。
- 全ページが「対応済み」か「指摘なし」になったら、版のタグを付けて次のステップへ進む。

## レビュー表の使い方(Googleスプレッドシート)

- 正本はGoogleドライブのスプレッドシート。`review-sheet.xlsx` はそのひな形(Googleドライブにアップロードし、「Googleスプレッドシートとして保存」で変換して使う)。
- シートは「１回目レビュー表」「２回目レビュー表」「最終レビュー」「使い方」の4枚。1シート=1回分のレビュー、1行=1ページ(サイト全体の行+全63ページ)。
- 列は左から「Claude・ChatGPT・Geminiの指摘 → 総括 → 見送った指摘と理由 → 対応内容(AIの指摘分)」、続けて「本人の指摘 → 対応内容(本人の指摘分)」「対応バージョン」「状態」「備考」。
- 1行目と左6列の固定・絞り込み・「状態」のプルダウンは設定済み。状態の値: `未着手` / `レビュー済み` / `対応中` / `対応済み` / `指摘なし` / `見送り`
- 「サイト全体」の行には、全ページに共通する指摘(用語の統一・デザインなど)を書く。

## Claude Codeへの渡し方

Claude CodeはGoogleドライブを直接編集できないため、次のどちらかでやり取りします。

- **読む**: スプレッドシートを「リンクを知っている全員が閲覧可」にしてURLを伝える(Claude CodeがCSVとして読み込む)。または、スプレッドシートを「ファイル → ダウンロード → CSV」で保存し、`reviews/inbox/` に置く(このフォルダはGitに入れない)。
- **書く**: Claude Codeは「総括」「見送った指摘と理由」「対応内容」「対応バージョン」「状態」の列を埋めたCSVを `reviews/inbox/` に出力するので、その列をスプレッドシートに貼り戻す。

## AIへのレビュー依頼文(ひな形)

ChatGPT・Gemini・Claude(チャット)に、同じ依頼文を送ります。`{ページ名}` と `{URL}` を差し替えてください。

```
次のWebページをレビューしてください。
デザインシステム比較サイト「DesignSystem Port」の1ページで、Apple(HIG)・Google(Material Design)・W3C(WCAG)・Nielsen Norman Groupの指針を比較し、AIの統合見解(AI解釈)を載せています。

ページ: {ページ名}
URL: {URL}

次の観点で、問題がある箇所だけを具体的に挙げてください(問題がなければ「指摘なし」)。
1. 事実の誤り(数値・基準番号・公式の記述との食い違い)。可能なら公式ページで確認した根拠を添える
2. 公式リンクの誤り・リンク切れ
3. 分かりにくい表現・専門用語の説明不足(読み手はデザイナー・エンジニア)
4. 他のページや同じページ内での矛盾・表記ゆれ
5. 図や表の見にくさ・表示崩れ(PCとスマートフォンの両方)
6. 抜けている重要な観点

回答は「観点番号/該当箇所/問題/修正案」の形の箇条書きでお願いします。
```

## 版(バージョン)の付け方

- 修正のステップ(②④⑥⑧⑨)を終えるごとに、マイナー番号を上げる(v0.2.0 → v0.3.0 …)。
- ステップの途中の小さな修正は、パッチ番号を上げる(v0.2.1 …)。
- 版ごとの変更内容は、リポジトリ直下の `CHANGELOG.md` とGitHubのReleasesに書く。
