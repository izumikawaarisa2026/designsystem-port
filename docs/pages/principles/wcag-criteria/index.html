WCAGの達成基準(デザイン)

各ページに出てくるWCAGの達成基準を、デザインで気をつけることに絞ってまとめた一覧

目的・役割
「2.5.8」「1.4.11」のような番号だけでは分かりにくい達成基準を、何を求めるか・なぜ必要か・デザインの要点・例外で引けるようにする
使い方
基準ごとに、何を求めるか・なぜ必要か・デザインの要点・主な例外と、その基準が関わるページへのリンクを並べている
関連するページ

レベルはA(最低限)・AA(一般的な目標)・AAA(より高い水準)の3段階。多くのガイドラインや調達の要件はAAを参照する(求められるレベルは、地域の法律や契約などで変わる)。このページでは目標になりやすいA・AAを中心に、各ページで触れているAAAも載せている。ターゲットのサイズやフォーカスのように、同じ観点でレベルだけが違う基準は1枚のカードにまとめ、レベルが上がるほど左の帯とラベルを濃くしている。説明はW3Cの解説書(Understanding WCAG 2.2)をもとにした要約で、正確な条件はリンク先で確かめる。

色とコントラスト

色の使い方と、文字・コンポーネントの見分けやすさ

1.4.1色の用途レベルA公式(Understanding WCAG 2.2) ↗

色だけで情報を伝えない。

なぜ必要か色の見分けがつきにくい人や、白黒の画面・強い外光のもとで見る人には、色の違いが伝わらないため。
デザインの要点エラー・必須・選択中・リンクなどは、色に加えてアイコン・文字・下線・形でも示す。色だけでリンクを区別するなら、周りの文字と3:1以上の明度差が要る。
主な例外色の違いに意味がない装飾は対象外。
関わるページリンク・ステータスメッセージ・バッジ・チェックボックス・チップ(Chips)・エラー表示・カラー
1.4.3コントラスト(最低限)レベルAA公式(Understanding WCAG 2.2) ↗

文字と背景のコントラスト比を確保する。

なぜ必要か弱視の人や、年齢とともに見えにくくなった人、色を見分けにくい人でも文字を読めるようにするため。
デザインの要点通常の文字は4.5:1以上、大きな文字(18pt以上、または14pt以上の太字。Webでおよそ24px/18.66px)は3:1以上。四捨五入しない(4.499:1は不合格)。ライト・ダークの両方で確かめる。
主な例外無効なコンポーネント、純粋な装飾、見えない文字、ロゴの文字。
関わるページバッジ・カラー・ダークモード
1.4.11非テキストのコントラストレベルAA公式(Understanding WCAG 2.2) ↗

コンポーネントの境界・状態の見た目と、意味のある図にコントラストを確保する。

なぜ必要かコンポーネントの境界や状態が見分けられないと、弱視の人などは、どこを押せるか・今どの状態かが分からないため。
デザインの要点ボタンや入力欄の枠、チェックの印、フォーカスの表示、選択状態を示す印、アイコンなどは、隣り合う色と3:1以上。文字やアイコンでコンポーネントだと分かるなら、枠そのものは必須ではない。状態どうしの差を3:1にする必要はない。
主な例外無効なコンポーネント、ブラウザ標準の見た目を変えていないコンポーネント、ロゴ・写真など見た目そのものが情報のもの。
関わるページボタン・ステータスメッセージ・バッジ・アプリバー・タブバー・タブ・チェックボックス・チップ(Chips)・ラジオボタン・トグルスイッチ・カラー・エレベーション・階層表現・アイコン・インタラクション状態・シェイプ・コーナーラジウス
1.4.8視覚的提示レベルAAA公式(Understanding WCAG 2.2) ↗

文章の見せ方を利用者が調整できる。

なぜ必要か読字障害・弱視・認知の障害がある人は、行が長い・行間が狭い・色の組み合わせが合わないと、文章を追いにくいため。
デザインの要点前景色と背景色を選べる、1行は80文字(日本語40文字)以内にできる、両端揃えにしない、行間1.5倍以上・段落間はそれ以上、200%に拡大しても横スクロールせずに読める。
主な例外AAAのため、多くのサイトの目標(AA)には含まれない。
関わるページダークモード・タイポグラフィ

文字とレイアウト

拡大・狭い幅・向きの変化で崩れないこと

1.4.4テキストのサイズ変更レベルAA公式(Understanding WCAG 2.2) ↗

文字を200%まで拡大しても内容と機能が失われない。

なぜ必要か弱視の人など、文字を大きくして読む人が、内容や機能を失わずに使えるようにするため。
デザインの要点固定の高さに文字を押し込めない。拡大で文字が切れたり重なったりしないかを確かめる。ページ全体のズームで満たしてもよい。
主な例外字幕と文字画像。
関わるページテキストフィールド・テキストエリア・タイポグラフィ
1.4.10リフローレベルAA公式(Understanding WCAG 2.2) ↗

幅320 CSS px相当でも、縦横2方向のスクロールなしで読める。

なぜ必要か拡大して読む人は、1行ごとに横へスクロールすると、どこを読んでいたかを見失いやすいため。
デザインの要点幅1280pxを400%に拡大した状態に当たる。狭い幅では1列に組み替える(横に並んだものは縦に積む)。
主な例外データ表・地図・図・動画・ゲームなど、2次元の配置が欠かせない部分。
関わるページテキストフィールド・テキストエリア・レスポンシブデザイン・レイアウト・スペーシング
1.4.12テキストの間隔レベルAA公式(Understanding WCAG 2.2) ↗

利用者が文字の間隔を広げても崩れない。

なぜ必要か読字障害や弱視の人などは、文字の間隔を広げると読みやすくなる。その設定で表示が崩れると、かえって読めなくなるため。
デザインの要点行の高さ1.5倍・段落の後2倍・字間0.12倍・単語間隔0.16倍に広げても、文字が切れたり重なったりしない。この値をデザインの初期値にする必要はない。
主な例外その言語でもともと使わない間隔(単語の間にスペースがない言語の単語間隔など)。
関わるページタイポグラフィ
1.3.4向き(orientation)レベルAA公式(Understanding WCAG 2.2) ↗

画面の向きを縦・横の一方に固定しない。

なぜ必要か端末を車いすなどに固定して使う人は、画面を回転させられないため。
デザインの要点縦向き・横向きのどちらでも使えるようにする。
主な例外小切手・ピアノのアプリ・VRなど、特定の向きが欠かせないもの。
関わるページレスポンシブデザイン
1.3.1情報及び関係性レベルA公式(Understanding WCAG 2.2) ↗

見た目で伝えている構造や関係を、構造としても伝える。

なぜ必要か読み上げで使う人には、見出しの大きさや余白によるまとまりといった、見た目の手がかりが伝わらないため。
デザインの要点見出し・リスト・表の見出しとデータの関係・余白でまとめたグループなどを、見た目だけでなく構造でも示す。余白だけのまとまりは読み上げでは伝わらない。
関わるページリスト・表(データテーブル)・テキストフィールド・テキストエリア・レイアウト・スペーシング

押せる範囲と入力の方法

指・ポインター・キーボードなど、入力の手段ごとの決まり

ターゲットのサイズレベルAAAAAA右ほど厳しい
2.5.8ターゲットのサイズ(最低限)レベルAA公式(Understanding WCAG 2.2) ↗

押す対象を24×24 CSS px以上にする(例外あり)。

なぜ必要か手の震えがある人や指の動きが不自由な人は、小さい対象を正確に押せず、隣の対象を押し間違えやすいため。
デザインの要点小さい場合は、各対象の中心に直径24pxの円を置いて、ほかの対象やその円と重ならない間隔があれば適合する。角丸が大きく内側に24px四方が収まらない対象は「小さい対象」として扱う。
主な例外5つ: ①間隔(上の円の条件)、②同じ機能の十分な大きさの代わりがある、③文中のリンクなど文章の行の中にある、④ブラウザが大きさを決めていて変えていない、⑤その大きさや配置が欠かせない(地図のピンなど)。
関わるページボタン・フローティングアクションボタン・タブバー・タブ・チェックボックス・ラジオボタン・セレクト(プルダウン)・スライダー・トグルスイッチ・レイアウト・スペーシング・シェイプ・コーナーラジウス
2.5.5ターゲットのサイズ(高度)レベルAAA公式(Understanding WCAG 2.2) ↗

押す対象を44×44 CSS px以上にする。

なぜ必要か手の震えや指の動きに不自由がある人に加えて、移動中や片手での操作など、誰でも押し間違えやすい場面でも確実に押せるようにするため。
デザインの要点Appleの44pt、Googleの48dpに近い、より高い水準。主要なボタンの目安にしやすい。
主な例外②〜⑤と同じ種類の例外がある(2.5.8の間隔の例外はない)。
関わるページボタン・タブバー・タブ・チェックボックス・ラジオボタン
2.5.1ポインタジェスチャレベルA公式(Understanding WCAG 2.2) ↗

2本指以上や軌跡で決まる操作に、1本指で軌跡のない代わりを用意する。

なぜ必要か複数の指を同時に使う操作や、決まった軌跡を描く操作は、指の動きが不自由な人や、口にくわえる棒・頭の動きで操作する道具を使う人には難しいため。
デザインの要点ピンチでの拡大には+/−のボタン、スワイプでの送りには前へ・次へのボタンなど。
主な例外軌跡そのものが欠かせない操作(手書きの署名など)。
関わるページ入力方法・ジェスチャー
2.5.2ポインタキャンセルレベルA公式(Understanding WCAG 2.2) ↗

押した瞬間ではなく、離したときに実行する。

なぜ必要か押した瞬間に実行すると、手の震えなどで誤って触れたときに、取り消す機会がないため。
デザインの要点誤って触れても、指をボタンの外へずらして離せば取り消せるようにする。
主な例外キーボードやピアノの鍵盤をまねるなど、押した瞬間の実行が欠かせないもの。
関わるページ入力方法・ジェスチャー
2.5.4動きによる起動レベルA公式(Understanding WCAG 2.2) ↗

端末を振る・傾けるなどの動きで行う機能に、画面上の代わりと、動きを切る手段を用意する。

なぜ必要か端末を振る・傾ける操作は、体の動きが不自由な人や端末を固定している人にはできないため。意図しない動きで誤って実行されることも防ぐ。
デザインの要点「振って元に戻す」には取り消しボタンも置き、動きへの反応を無効にできるようにする。
主な例外OSのアクセシビリティ機能など、支援の仕組みで動きを使う場合。
関わるページ入力方法・ジェスチャー
2.5.7ドラッグ動作レベルAA公式(Understanding WCAG 2.2) ↗

ドラッグで行う機能に、ドラッグしない1本指の代わりを用意する。

なぜ必要かドラッグは押したまま正確に動かし続ける操作で、手の動きが不自由な人や、頭の動き・視線で操作する道具を使う人には難しいため。
デザインの要点スライダーは溝を押した位置へつまみを移す、並べ替えはメニューから選べる、シートの高さはグラバーを押して切り替える、など。
主な例外ドラッグが欠かせない場合、ブラウザが決めていて変えていないドラッグ。
関わるページボトムシート・スライダー・入力方法・ジェスチャー
2.5.6入力メカニズムの共存レベルAAA公式(Understanding WCAG 2.2) ↗

使える入力手段(タッチ・マウス・キーボードなど)をコンテンツ側で制限しない。

なぜ必要か使いやすい入力手段は人によって違い、同じ人でも場面で切り替えるため(タブレットにキーボードをつなぐ、など)。
デザインの要点タッチの端末でもマウスやキーボードを使えるようにする。
主な例外セキュリティや必要不可欠な場合。
関わるページ入力方法・ジェスチャー
2.1.1キーボードレベルA公式(Understanding WCAG 2.2) ↗

すべての機能をキーボードで操作できる。

なぜ必要か画面を見ずに使う人や、手の動きが不自由でマウスを使えない人は、キーボードか、キーボードの代わりになる装置(スイッチ・音声入力など)で操作するため。
デザインの要点ポインター前提になりやすいスライダー・ドラッグ・メニューなども、キーボードで操作できるようにする。
主な例外手書きなど、軌跡そのものが欠かせない入力。
関わるページタブ・チップ(Chips)・セレクト(プルダウン)・スライダー・入力方法・ジェスチャー
2.1.2キーボードトラップなしレベルA公式(Understanding WCAG 2.2) ↗

キーボードのフォーカスが抜け出せなくならない。

なぜ必要かキーボードだけで使う人は、フォーカスが抜け出せなくなると、そこから先のページを使えなくなるため。
デザインの要点ダイアログなどでフォーカスを閉じ込める場合も、Escキーなどで閉じて外に戻れるようにする。
関わるページ入力方法・ジェスチャー

フォーカスとホバー

今どこを操作しているかが分かり、勝手に動かないこと

2.4.3フォーカス順序レベルA公式(Understanding WCAG 2.2) ↗

フォーカスの順番が、意味と操作の流れに沿っている。

なぜ必要かキーボードや読み上げで使う人は、フォーカスの順番どおりに内容をたどる。順番が飛ぶと、意味や操作の流れがつかめないため。
デザインの要点見た目の並びと読む順番をそろえる。ダイアログを閉じたら、開いたボタンにフォーカスを戻す。
関わるページ入力方法・ジェスチャー
フォーカスの見え方レベルAAAAAA右ほど厳しい
2.4.7フォーカスの可視化レベルAA公式(Understanding WCAG 2.2) ↗

キーボードで操作するとき、フォーカスの位置が見える。

なぜ必要かキーボードで操作する人は、フォーカスの位置が見えないと、今どこを操作しているのか分からないため。
デザインの要点フォーカスの表示を消さない。色の変化だけに頼らず、輪郭線などで示すと分かりやすい。
関わるページボタン・インタラクション状態
2.4.13フォーカスの外観レベルAAA公式(Understanding WCAG 2.2) ↗

フォーカスの表示を十分な大きさとコントラストにする。

なぜ必要か細い・薄いフォーカスの表示は、弱視の人や画面から離れて見る人には見つけにくいため。
デザインの要点コンポーネントの周りを2 CSS pxの太さで囲んだ面積以上で、フォーカスの前後の同じピクセルどうしで3:1以上の変化をつける。
主な例外ブラウザが決めていて作者が調整できないフォーカス表示。
関わるページインタラクション状態
隠されないフォーカスレベルAAAAAA右ほど厳しい
2.4.11隠されないフォーカス(最低限)レベルAA公式(Understanding WCAG 2.2) ↗

フォーカスしたコンポーネントが、固定ヘッダーやバナーなど作者が作った重なりで完全に隠れない。

なぜ必要かフォーカスした先が隠れると、キーボードで操作する人は、今どこにいるのかが分からなくなるため。
デザインの要点上部の固定ヘッダーや下部のCookieバナーの下にフォーカスが入り込まないよう、スクロールの位置を調整する。
主な例外利用者が自分で開いた内容で、フォーカスを移さずに閉じられるもの。
関わるページエレベーション・階層表現
2.4.12隠されないフォーカス(高度)レベルAAA公式(Understanding WCAG 2.2) ↗

フォーカスしたコンポーネントが、一部も隠れない。

なぜ必要か一部でも隠れると、フォーカスしたコンポーネントが何かを見分けにくくなる場合があるため。
デザインの要点固定ヘッダーやバナーに少しでもかかるなら、スクロールの位置を調整するか、重なりそのものをなくす。
関わるページエレベーション・階層表現
3.2.1フォーカス時レベルA公式(Understanding WCAG 2.2) ↗

フォーカスが当たっただけで、文脈を変えない。

なぜ必要かフォーカスを当てるたびに画面が変わると、キーボードや読み上げで使う人は、何が起きたのか分からずに迷うため。
デザインの要点フォーカスしただけで別のページへ遷移する・新しいウィンドウを開く・送信する、といったことを起こさない。
関わるページタブ・セレクト(プルダウン)
1.4.13ホバー又はフォーカスで表示されるコンテンツレベルAA公式(Understanding WCAG 2.2) ↗

ホバーやフォーカスで出る内容(ツールチップなど)の3つの条件を満たす。

なぜ必要かツールチップなどが周りの内容を隠したり、すぐ消えたりすると、拡大して見る人や読むのに時間がかかる人が、内容を読み取れないため。
デザインの要点①ポインターを動かさずに消せる(Escキーなど)、②内容の上にポインターを移しても消えない、③離れるか消すまで勝手に消えない。
主な例外入力の誤りの表示など、内容がほかの情報を隠さないもの。ブラウザが出すツールチップ。
関わるページツールチップ

動きと時間

動きで人を傷つけない、時間で追い立てない

2.2.1期限調節可能レベルA公式(Understanding WCAG 2.2) ↗

時間制限を延長・解除できるようにする。

なぜ必要か読む・操作するのに時間がかかる人(視覚・運動・認知の障害がある人など)は、制限時間の中で終えられないことがあるため。
デザインの要点「元に戻す」などの操作を持つ通知を時間で消すと、操作が間に合わない人がいる。時間で消さないか、延長・解除できるようにする。
主な例外リアルタイムの競りなど、時間制限が欠かせないもの。20時間を超える制限。
関わるページスナックバー(トースト)・ウィザード(ステップ形式の入力)
2.2.2一時停止・停止・非表示レベルA公式(Understanding WCAG 2.2) ↗

自動で始まり5秒を超えて続く動き・点滅・スクロールを止められる。

なぜ必要か動く・変わる内容は注意をそらし、集中しにくい人が読むのを妨げる。読むのに時間がかかる人は、動いている間に読み終えられないため。
デザインの要点自動で回るカルーセルには停止ボタンを置く。自動で更新される情報も止めたり隠したりできるようにする。
主な例外動きが欠かせない場合。
関わるページカルーセル・モーション
2.3.13回の閃光、又は閾値以下レベルA公式(Understanding WCAG 2.2) ↗

1秒間に3回を超えて点滅させない。

なぜ必要か光の点滅は、光過敏性てんかんの人に発作を起こすことがあるため。
デザインの要点注意を引くための点滅は避け、色の変化やアイコンなど点滅しない方法で示す。
主な例外点滅の明るさや面積が閾値以下の場合。
関わるページモーション
2.3.3インタラクションによるアニメーションレベルAAA公式(Understanding WCAG 2.2) ↗

操作をきっかけに起きる動きを、無効にできる。

なぜ必要か前庭障害がある人などは、画面の大きな動きで、めまいや吐き気を起こすことがあるため。
デザインの要点視差スクロールなど装飾の動きは、OS・ブラウザの「動きを減らす」設定に従って止める。
主な例外機能や情報に欠かせない動き。
関わるページモーション

音と映像

音を止められ、音だけで伝えない

1.4.2音声の制御レベルA公式(Understanding WCAG 2.2) ↗

自動で3秒を超えて鳴る音を、止めるか個別に音量を調整できる。

なぜ必要かページの音が鳴っていると、読み上げで使う人は、読み上げの声が聞き取れなくなるため。
デザインの要点自動再生の音は避け、鳴らすなら停止の手段をすぐ見つかる場所に置く。
主な例外3秒以内に終わる音。
関わるページサウンド
1.4.7背景音の小さい又はない音声レベルAAA公式(Understanding WCAG 2.2) ↗

録音した音声が中心の内容で、背景音をなくす・切れる・20dB以上小さくする。

なぜ必要か聞こえにくい人は、背景音があると話し声を聞き分けにくいため。
デザインの要点ナレーションに背景音楽を重ねるなら十分に小さくする。
主な例外音声CAPTCHA・音声ロゴ・歌など。
関わるページサウンド
1.2.1音声だけ及び映像だけ(収録済み)レベルA公式(Understanding WCAG 2.2) ↗

録音した音声だけ・映像だけの内容に、代わりを用意する。

なぜ必要か聞こえない人は音声の内容を、見えない人は映像の内容を受け取れないため。
デザインの要点音声だけなら書き起こし、映像だけなら書き起こしか音声の説明を用意する。
主な例外代わりのメディアであることが明らかなもの。
関わるページサウンド
1.2.2キャプション(収録済)レベルA公式(Understanding WCAG 2.2) ↗

録音した映像の音声に字幕を付ける。

なぜ必要か聞こえない・聞こえにくい人が、会話や重要な音の内容を受け取れるようにするため。
デザインの要点会話や重要な音を字幕で伝える。
関わるページサウンド

文言・ラベル・ナビゲーション

何のためのコンポーネントか、今どこにいるかを言葉で伝える

1.1.1非テキストコンテンツレベルA公式(Understanding WCAG 2.2) ↗

意味のある画像やアイコンに、文字の代わりを用意する。

なぜ必要か読み上げで使う人には、画像やアイコンの意味がそのままでは伝わらないため。文字にしておけば、読み上げ・点字・拡大などの形に変えられる。
デザインの要点操作のアイコンには、見た目ではなく目的の名前を付ける(「虫めがね」ではなく「検索」)。飾りの画像は読み上げない。
主な例外装飾だけの画像。
関わるページアイコン
1.3.3感覚による特性レベルA公式(Understanding WCAG 2.2) ↗

操作の説明を、形・大きさ・位置・音だけに頼らない。

なぜ必要か見えない人や位置関係をつかみにくい人は、形・大きさ・位置だけの説明では、どれを指すのか特定できないため。
デザインの要点「右の丸いボタン」ではなく「[送信]ボタン」のように、コンポーネントの名前も書く。
関わるページ文章・UXライティング
2.4.2ページタイトルレベルA公式(Understanding WCAG 2.2) ↗

ページに、主題や目的を表すタイトルを付ける。

なぜ必要かタイトルは読み上げで最初に読まれ、タブや履歴にも出る。中身を読む前に、どのページかを判断できるようにするため。
デザインの要点画面ごとに内容を表すタイトルにする。1つのURLで画面が切り替わる場合も、画面ごとにタイトルを変える。
関わるページ文章・UXライティング
リンクの目的レベルAAAAAA右ほど厳しい
2.4.4リンクの目的(コンテキスト内)レベルA公式(Understanding WCAG 2.2) ↗

リンクの目的が、リンクの文言か周りの文脈から分かる。

なぜ必要か読み上げで使う人は、リンクだけを一覧にして選ぶことがある。「こちら」だけでは、行き先が分からないため。
デザインの要点「こちら」「詳しくはここ」だけのリンクにしない。
主な例外誰にとっても目的が分からないリンク。
関わるページリンク・ページネーション
2.4.9リンクの目的(リンクのみ)レベルAAA公式(Understanding WCAG 2.2) ↗

リンクの目的が、リンクの文言だけで分かる。

なぜ必要か周りの文を読まなくても、リンクの文言だけで行き先が分かれば、誰にとっても選びやすくなるため。
デザインの要点周りの文を読まなくても行き先が分かる文言にする(「詳しく」ではなく「料金プランの詳細」)。
主な例外誰にとっても目的が分からないリンク。
関わるページリンク
2.4.5複数の手段レベルAA公式(Understanding WCAG 2.2) ↗

ページにたどり着く方法を2つ以上用意する。

なぜ必要か得意な探し方は人によって違うため(検索の方が使いやすい人も、階層をたどる方が分かりやすい人もいる)。
デザインの要点ナビゲーションに加えて、サイト内検索やサイトマップを置く。
主な例外手続きの途中や結果の画面。
関わるページ検索フィールド
2.4.6見出し及びラベルレベルAA公式(Understanding WCAG 2.2) ↗

見出しとラベルが、主題や目的を表す。

なぜ必要か内容が分かる見出し・ラベルがあれば、読むのに時間がかかる人や読み上げで使う人も、目的の場所を早く見つけられるため。
デザインの要点見出しやラベルを置くこと自体は求めない。置いたなら、内容が分かる言葉にする(1語でもよい)。
関わるページ文章・UXライティング
2.4.8現在位置レベルAAA公式(Understanding WCAG 2.2) ↗

一連のページの中の今の位置が分かる。

なぜ必要か長い手続きや大きいサイトでは、今どこにいるのかを見失いやすいため(特に、記憶や注意に障害がある人)。
デザインの要点パンくずリストやステップの表示などで示す。置けば自動で適合するわけではない。
関わるページパンくずリスト
2.5.3ラベルを含む名前レベルA公式(Understanding WCAG 2.2) ↗

見えるラベルの言葉を、支援技術向けの名前にも含める。

なぜ必要か音声入力で使う人は、見えるラベルの言葉を言って操作する。その言葉が名前に含まれていないと反応しないため。
デザインの要点見えるラベルの言葉をそのまま、できれば名前の先頭に入れる(「送信」と書いたボタンの名前を「フォームを送る」にしない)。
関わるページアイコン
3.1.5読解レベルレベルAAA公式(Understanding WCAG 2.2) ↗

難しい文には、補足か易しい版を用意する。

なぜ必要か読解に障害がある人や、その言語に慣れていない人でも、内容を理解できるようにするため。
デザインの要点前期中等教育(9年の学校教育)を超える読解力が要る文が対象。
主な例外固有名詞や題名。
関わるページ文章・UXライティング
3.2.3一貫したナビゲーションレベルAA公式(Understanding WCAG 2.2) ↗

複数のページで繰り返すナビゲーションを、いつも同じ順番で並べる。

なぜ必要か並びが同じなら、場所を覚えて使える。ページごとに変わると、拡大して見る人・読み上げで使う人・認知に障害がある人は、探し直しになるため。
デザインの要点ヘッダーやサイドナビの項目の順番をページごとに変えない。
主な例外利用者が自分で並びを変えた場合。
関わるページドロワー/サイドナビ・アプリバー・タブバー
3.2.4一貫した識別性レベルAA公式(Understanding WCAG 2.2) ↗

同じ働きのコンポーネントを、ページをまたいで一貫して識別できる。

なぜ必要か同じ働きのものが同じ名前なら、一度覚えれば使い回せる。ページごとに違うと、別の機能だと思われやすいため。
デザインの要点共通の検索・アカウントなどのアイコンボタンには、どのページでも同じ名前を付ける。
主な例外文脈に合わせた小さな違い(「前のページ」など)。
関わるページリンク・アイコン
3.2.6一貫したヘルプレベルA公式(Understanding WCAG 2.2) ↗

問い合わせ先・FAQなどのヘルプを、ページをまたいで同じ位置に置く。

なぜ必要か困ったときに、助けを探す手間を減らすため。特に認知に障害がある人は、場所が変わるとヘルプを見つけにくい。
デザインの要点ヘルプを置くこと自体は求めない。置くなら同じ順番の位置にする。
主な例外利用者が自分で変えた場合。
関わるページアプリバー

入力とエラー

入力しやすく、誤りに気づいて直せること

1.3.5入力目的の特定レベルAA公式(Understanding WCAG 2.2) ↗

入力欄の目的(名前・メールアドレスなど)を判別できるようにする。

なぜ必要か入力欄の目的が機械に分かれば、自動入力などで入力を助けられる。記憶や文字の入力に負担がある人の手間が減るため。
デザインの要点ブラウザの自動入力が効くようにし、入力の手間を減らす。
関わるページテキストフィールド・テキストエリア
3.2.2入力時レベルA公式(Understanding WCAG 2.2) ↗

設定を変えただけで、事前の説明なしに文脈を変えない。

なぜ必要か予期しない遷移や送信は、見えない人や認知に障害がある人を混乱させ、意図しない操作につながるため。
デザインの要点プルダウンで選んだだけで遷移・送信しない。実行は「移動」「送信」ボタンで行う。スイッチの切り替えで画面を変えるなら事前に知らせる。
主な例外事前に知らせている場合。
関わるページセレクト(プルダウン)・トグルスイッチ
3.3.1エラーの特定レベルA公式(Understanding WCAG 2.2) ↗

入力の誤りを自動で見つけたら、その項目を特定し、文字で説明する。

なぜ必要か色や枠の変化だけでは、見えない人や色を見分けにくい人に誤りが伝わらないため。どこがどう誤っているかが分からないと直せない。
デザインの要点色や枠の変化だけでなく、どの欄がどう誤っているかを文字で示す。
関わるページステータスメッセージ・エラー表示
3.3.2ラベル又は指示レベルA公式(Understanding WCAG 2.2) ↗

入力が必要なところに、ラベルか説明を用意する。

なぜ必要か何を入力すればよいかが分からないと、誤りや入力のやり直しが増えるため(特に認知に障害がある人)。
デザインの要点プレースホルダーだけをラベルにしない。書式や必須かどうかも示す。説明を増やしすぎない。
関わるページテキストフィールド・テキストエリア・ウィザード(ステップ形式の入力)・文章・UXライティング
3.3.3エラーの修正提案レベルAA公式(Understanding WCAG 2.2) ↗

誤りの直し方が分かっていれば、訂正案を示す。

なぜ必要か直し方が分からないと、先へ進めなくなる人がいるため(特に学習・認知に障害がある人)。
デザインの要点「8文字以上で入力してください」のように具体的に書く。
主な例外セキュリティや目的を損なう場合(パスワードなど)。
関わるページエラー表示
3.3.4誤り防止(法的・金融・データ)レベルAA公式(Understanding WCAG 2.2) ↗

法的・金融的な確約、データの変更・削除、試験の送信で、誤りを防ぐ手段を用意する。

なぜ必要か法律やお金に関わる手続き、データの削除は、誤ると取り返しがつかないことがあるため。入力の誤りに気づきにくい人もいる。
デザインの要点取り消せる・検査して直す機会を与える・送信前に確認できる、のどれかを備える。
主な例外対象のページだけにかかる。
関わるページエラー表示
3.3.7冗長な入力レベルA公式(Understanding WCAG 2.2) ↗

同じ手続きの中で、前に入力した情報をもう一度入力させない。

なぜ必要か同じ情報の入力を繰り返すのは、記憶や入力に負担がある人には大きな手間で、誤りも増えるため。
デザインの要点自動で入れておくか選べるようにする(「配送先と同じ」のチェックなど)。エラーで戻しても入力を消さない。
主な例外セキュリティ上の再入力、入れ直すこと自体が目的の場合、前の情報が無効になった場合。
関わるページバリデーション・ウィザード(ステップ形式の入力)

支援技術への伝え方

見た目と同じことを、読み上げなどにも伝える

4.1.2名前(name)・役割(role)・値(value)レベルA公式(Understanding WCAG 2.2) ↗

コンポーネントの名前・役割・状態を、支援技術が取得できるようにする。

なぜ必要か支援技術は、コンポーネントの名前・役割・状態を受け取って利用者に伝える。伝わらないと、それが何か・押せるか・今どの状態かが分からないため。
デザインの要点ボタンが押されているか、メニューが開いているか、選択中かなどの状態も伝える。ブラウザ標準のコンポーネントなら多くは自動で伝わり、独自に作ったコンポーネントは配慮が要る。
関わるページボタン・バッジ・サイドシート・セグメントコントロール・タブ・チェックボックス・チップ(Chips)・ラジオボタン・セレクト(プルダウン)・スライダー・トグルスイッチ・テキストフィールド・テキストエリア・アイコン・インタラクション状態
4.1.3ステータスメッセージレベルAA公式(Understanding WCAG 2.2) ↗

フォーカスを移さずに出る知らせを、支援技術にも伝える。

なぜ必要か見えている人は画面の変化で知らせに気づけるが、読み上げで使う人は、知らせが読み上げられないと気づけないため。
デザインの要点「保存しました」「5件見つかりました」などは、控えめな知らせとして読み上げられるようにする。緊急の警告は割り込んで読み上げる。
関わるページステータスメッセージ・エンプティステート・プログレスインジケーター(ローディング)・スナックバー(トースト)
