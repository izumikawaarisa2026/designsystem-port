アクセシビリティ

4つのガイドラインが、アクセシビリティという概念をどう捉え、どう体系立てているかを比較する

AI解釈 ― まず結論

「アクセシビリティ」という言葉が指す範囲は、4系列でかなり異なります。WCAGは適合の可否を判定できる規格として、知覚可能・操作可能・理解可能・堅牢という4原則(POUR)を定義しています。一方でApple・Google・Nielsen Norman Groupは、規格というより実践的な指針や考え方として、それぞれ独自の言葉でアクセシビリティを語っています。

なかでもNielsen Norman Groupは、アクセシビリティを「チェックリストではなく心構え(マインドセット)」だと明言しており、WCAGの規格的な性格とは対照的です。Appleは視覚・聴覚・可動性・発話・認知という障害の種類ごとに実践的なガイダンスを示し、Googleは「制約を機会に変える」という前向きな捉え方を打ち出しています。

本サイトが各コンポーネントページの「アクセシビリティ」欄でPOURの語彙を採用しているのは、数ある考え方の中でWCAGが最も具体的で、かつ検証可能だからです。ただし、それが唯一の正解というわけではありません。他の3系列の視点も知っておくと、アクセシビリティへの理解がより立体的になります。

WCAGの番号とレベルの読み方

原則4つ
例: 2 = 操作可能(Operable)
ガイドライン13
例: 2.5 = 入力方法(Input Modalities)
達成基準番号付き
例: 2.5.8 = ターゲットのサイズ(最低限)

番号の先頭の数字が原則を表します(1=知覚可能・2=操作可能・3=理解可能・4=堅牢)。各達成基準には適合レベルがあり、A=最低限、AA=実務で一般的な目標(法令や社内基準の多くがAAを求めます)、AAA=より高い水準(すべてのページで満たすことは求められていません)です。なお、W3CのAPG(ARIA Authoring Practices Guide)は実装の参考例で、適合の基準ではありません。

Apple
Human Interface Guidelines ― Accessibility
Vision(視覚)
色だけに頼らず、形やアイコンなど視覚的な手がかりを追加して情報を伝えるべきという指針。色覚特性により特定の色の組み合わせ(赤緑・青橙など)の判別が難しい人がいることに配慮する。
Hearing(聴覚)
音声情報には字幕や代替テキストなど、聴覚以外でも受け取れる手段を用意すべきという指針。
Mobility(可動性)
運動機能に制約がある人でも操作できるよう、タップ領域の確保や代替の入力手段を用意すべきという指針。
Speech(発話)
音声入力に頼らず操作できる代替手段を用意すべきという指針。
Cognitive(認知)
認知的な負荷を減らし、分かりやすく一貫した設計にすべきという指針。

Material Design ― アクセシビリティ原則
アクセシビリティをデフォルトに
アクセシビリティ基準はマテリアルの各コンポーネントに組み込まれており、包括的な製品設計の基盤になっているという考え方。多様なユーザーを想定することが、後からの手戻り(再設計)や技術的負債を防ぐことにもつながるとしている。
要件を機会として捉える
WCAGが定める最低限の要件は特定のニーズに応えるものだが、その制約の中で生まれた工夫(ダークモード・読み上げ・音声認識など)が結果的に幅広いユーザーの助けになってきたという考え方。

W3C
WCAG 2.2 ― POUR(4原則・13ガイドライン)
Perceivable(知覚可能)仕様書へ ↗

情報やUIコンポーネントは、ユーザーが知覚できる形で提示されなければならないという原則。

1
1.1 Text Alternatives
非テキストコンテンツに代替テキストを用意すべきという指針。
2
1.2 Time-based Media
動画・音声に代替手段を用意すべきという指針。
3
1.3 Adaptable
情報や構造を失わずに異なる形式でも提示できるべきという指針。
4
1.4 Distinguishable
前景と背景を区別しやすくすべきという指針(色のみによる区別の禁止など)。
Operable(操作可能)仕様書へ ↗

UIコンポーネントとナビゲーションは操作可能でなければならないという原則。

1
2.1 Keyboard Accessible
すべての機能をキーボードだけで利用できるべきという指針。
2
2.2 Enough Time
内容を読んだり操作したりするのに十分な時間を与えるべきという指針。
3
2.3 Seizures and Physical Reactions
発作等を誘発する設計をしてはならないという指針。
4
2.4 Navigable
現在地の把握やナビゲートを助ける手段を提供すべきという指針(リンクの目的など)。
5
2.5 Input Modalities
多様な入力方法での操作性を高めるべきという指針(タップ領域など)。
Understandable(理解可能)仕様書へ ↗

情報とUIの操作方法は理解可能でなければならないという原則。

1
3.1 Readable
テキストを読みやすく理解しやすくすべきという指針。
2
3.2 Predictable
見た目や動作を予測可能にすべきという指針。
3
3.3 Input Assistance
入力ミスを避け、修正を助けるべきという指針。
Robust(堅牢)仕様書へ ↗

コンテンツは支援技術を含む様々なユーザーエージェントで確実に解釈できるべきという原則。

1
4.1 Compatible
現在・将来のユーザーエージェントとの互換性を最大化すべきという指針。

Nielsen Norman Group
Accessibility and Inclusivity: Study Guide
アクセシビリティ = 心構え
アクセシビリティとインクルーシブデザインは、手続き・規制・チェックリストの集まりではなく、マインドセットであるという考え方。
アクセシブルデザイン
視覚・聴覚・認知・情緒・運動面で困難を抱えるユーザーを助けるデザインという整理。
インクルーシブデザイン
人種・性別・宗教など多様な背景を持つユーザーを歓迎し、それらが体験の妨げにならないようにする設計という整理。
