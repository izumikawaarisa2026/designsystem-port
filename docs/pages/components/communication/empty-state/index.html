コンポーネント / 空状態SPEC No. 038

空状態

表示する中身がない画面(空状態)の見せ方です。

コンポーネントイメージ(共通形状)
📭
まだアイテムがありません
お気に入りに追加するとここに表示されます
+ 追加する空状態

「状況の説明+次の行動への導線」が4系列に共通する考え方。

目的・役割
中身がない理由を伝え、次にできることへ案内する
よく使われる場面
初めて使うときの空の一覧、検索結果0件、完了済みのToDoリスト
似た部品との違い
読み込み中の見せ方はローディング状態

四系列デザインシステム比較

AI解釈 ― 総括

AppleにもGoogleにも、現行の「空状態」の専用コンポーネントはありません。Appleは文章の書き方のページ(Writing)の中で触れ、Googleは旧世代(Material Design 1)のパターンページにだけ記述があります。

最も具体的なのはNielsen Norman Groupで、空状態には「今の状況を伝える」「使い方を教える」「次の行動へ案内する」の3つの役割があるとしています。AppleのWritingのページも、次にできる操作を案内し、可能ならそのボタンやリンクを置く点で同じ考え方です。

W3Cには空状態の専用の決まりはありませんが、検索結果0件のような結果は、ステータスメッセージとして支援技術にも伝える(4.1.3)必要があります。

Apple
Human Interface Guidelines ― Writing(空の画面の文言)
空の画面

空の画面に、次にできる操作を添える(概念図・系列識別色)

専用コンポーネントなし
「空状態」という単独のコンポーネントはなく、文章の書き方(Writing)のページで空の画面の文言に触れている
推奨される使用シーン
  • ToDoリストや保存済みアイテムが1件もない画面で、次にできる操作を案内したい時
サイズ
数値基準なし

完了済みのToDoリストや空のブックマークフォルダのような空の画面を、歓迎の気持ちを伝えたりアプリの使い方を伝えたりする機会にでき、次にできる操作を案内し、可能ならそのためのボタンやリンクを置くよう勧めている。

例外・許容ケース
空状態は基本的に一時的なものなので、消えてしまう可能性のある重要な情報をそこに置くべきではないとしている。なお、Tab barsのページは、機能が一時的に使えないときもタブを消したり無効にしたりしないよう求めている。
アクセシビリティ(WCAG基準)
記載なし。Writingのページは、誰にでも伝わるように、平易な言葉でアクセシビリティとローカライズを意識して書くよう勧めている。
ユースケース
  • 空の画面では次にできる操作を案内し、可能ならそのボタンやリンクを置く
  • 消えてしまう可能性のある重要な情報は空状態に置かない

Nielsen Norman Group
Designing Empty States in Complex Applications
空状態(3つの役割)

状況の説明+次の行動への導線(概念図・系列識別色)

空状態を「システムの状態を伝える」「学習の機会にする」「主なタスクへ導く」という3つの役割を持つ設計対象として位置づける(数値基準ではなく原則)
推奨される使用シーン
  • 検索結果0件やリスト未設定など、データがない理由をユーザーに明示したい時
  • 初めて使う機能の使い方を、空状態の文言を通じて教えたい時
サイズ
数値基準なし

(1)「該当期間のレコードがありません」のように状況を明示して、読み込み中なのか本当にデータがないのかの混乱を避ける、(2)「お気に入りに追加するとここに表示されます」のように操作方法を教える学習機会として使う、(3)「作成」ボタンなど次に取るべき行動への直接の導線を用意する、という3つの指針を挙げている。

例外・許容ケース
3つの指針は数値基準ではなく、原則としての言及。
アクセシビリティ(WCAG基準)
根拠となる原則 ― POURのような適合区分ではなく、システム状態の伝達・学習支援・タスク導線という観点からの設計指針。
ユースケース
  • 空欄を放置せず、状況を明示するメッセージを必ず入れる
  • ユーザーを責めるトーンを避け、次の行動を案内する
