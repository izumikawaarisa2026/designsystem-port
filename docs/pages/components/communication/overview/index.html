情報伝達の使い分け

利用者に何かを知らせるコンポーネントを、4つの判断軸と比較表で選び分けるためのページ

目的・役割
作業を止めるか・対応が要るか・どう消えるか・どこに出すかで、知らせ方のコンポーネントを見分けられるようにする
扱うコンポーネント
モーダルダイアログ、バナー、スナックバー、ステータスメッセージ、トースト、ツールチップ
関連するページ
画面の上に重ねて内容や操作を出すコンポーネントはオーバーレイの使い分け
AI解釈 ― 総括

6つの知らせ方は、①作業を止めるか ②利用者の対応が要るか ③どう消えるか ④画面のどこに出すかという4つの軸で整理できる(詳しくは下の「4つの判断軸」を参照)。作業を止めるのはモーダルダイアログだけで、答えを得るまで先へ進ませたくない場面に限って使う。ほかの5つは作業を止めずに知らせる。

スナックバーとトーストの違いは取り消しなどの操作を持たせるか。バナーは自動で消えず、画面に残り続けるお知らせだ。ステータスメッセージは成功・情報・注意・エラーという状態の伝え方そのもので、バナーやスナックバーの形で出すこともある(AI解釈)。ツールチップは、知らせるというよりコンポーネントの意味を補う短い説明だ。

ただし、表示がどれだけ続くか・利用者の対応が必要か・どれだけ急ぎか(緊急度)は別々の軸で、残り続ける通知が必ず対応を求めるとは限らない(Nielsen Norman Groupの「アクション必須/受け身」の分類は、対応の必要性の軸)。フルスクリーンダイアログ・ボトムシート・サイドシートなど、画面の上に重ねて内容や操作を出すコンポーネントの使い分けは「オーバーレイの使い分け」ページで比べている。

「利用者の対応が必要か」は、表示がどれだけ続くか・どれだけ急ぎか(緊急度)とは別の軸だ。画面に残り続けるバナーでも、必ず対応が必要とは限らない。Nielsen Norman Groupの「アクション必須/受け身(パッシブ)」の分類は、この対応の必要性の軸として読む。スナックバーの操作(元に戻すなど)は任意で、押さなくても作業は続けられる。

トーストは時間で自動的に消える。スナックバーも基本は自動で消えるが、操作を持つなら自動で消さないのが安全。ツールチップは時間ではなく、ポインターやフォーカスが外れたときに消える(1.4.13)。バナーとモーダルダイアログは、閉じるか対応するまで残る。ステータスメッセージは内容で変わり、入力の誤りは直すまで問題の場所の近くに残す(NN group)。

くわしい説明

モーダルダイアログ=中央、バナー=上部、スナックバー/トースト=下部、ステータスメッセージ=操作した場所や問題の場所の近く、ツールチップ=指しているコンポーネントの近く。

6つのコンポーネント

モーダルダイアログ
作業を止めて、答え(OK・キャンセルなど)を求める知らせ方。
推奨取り消せない操作の確認など、答えを得るまで先へ進ませたくない時
NG答えのいらない知らせで済む時(→バナー・スナックバー)
バナー
画面に残り続ける、作業を止めないお知らせ。
推奨オフライン状態など、対応するまで気づかせ続けたい時
NG一度きりの結果の知らせで十分な時(→スナックバー)
スナックバー
操作の完了を知らせる。基本は自動で消えるが、元に戻すなど1つの操作を持つなら自動で消さないのが安全。
推奨取り消せる操作の完了を知らせたい時(例: 削除した→元に戻す)
NG操作を持たせる必要がない、ただの知らせで十分な時(→トースト)
ステータスメッセージ
操作の結果や今の状態(成功・情報・注意・エラー)を、作業を止めずに伝えるメッセージ。
推奨保存の完了・入力の誤り・検索結果の件数などを知らせたい時
NG答えを得るまで先へ進ませたくない時(→モーダルダイアログ)
トースト
操作ボタンを持たない、最も軽い一時的なメッセージ。
推奨取り消しなどの操作を持たない、ごく軽いお知らせをしたい時
NG元に戻すなどの操作を持たせたい時(→スナックバー)
ツールチップ
ポインターを重ねたときやフォーカスしたときに出る、短い一言の補足説明。
推奨アイコンの意味など、短い補足を添えたい時
NG押せる操作を含めたい時(→ダイアログやシートなど)

関連するページ(この比較には含めていないコンポーネント)

画面の上に重ねて内容や操作を出すコンポーネント(フルスクリーンダイアログ・ボトムシート・サイドシートなど)は「オーバーレイの使い分け」で、同じ場所で開閉して詳しい内容を見せるコンポーネントは「アコーディオン」で比べている。プログレスインジケーター・バッジ・空状態・ローディング状態は、何かが起きたことを知らせるのではなく「今どんな状態か」を示すこと自体が目的のため、この比較には含めていない。
