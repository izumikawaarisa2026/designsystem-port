コンポーネント / Navigationの選び方SPEC No. 012.5

Navigationの選び方

ナビゲーションのコンポーネントを、どこへ移るかと画面の広さから選び分けるためのページ

目的・役割
名前や見た目が似たナビゲーション(バー・ドロワー・サイドナビ・タブなど)を、移る範囲と画面の広さで選べるようにする
扱うコンポーネント
タブバー、ナビゲーションドロワー、サイドナビ、アプリバー、タブ、セグメントコントロール、パンくずリスト、ページネーション
関連するページ
タブとセグメントの細かい違いはタブとセグメントの使い分け
AI解釈 ― 総括

まず「どの範囲を移るか」で分ける。アプリの主な場所ならタブバー・ドロワー・サイドナビ、1つ上へ戻るならアプリバー、同じ画面の中ならタブかセグメントコントロール、一覧の続きならページネーションだ。

主な場所の切り替えは画面の広さで決まる。スマートフォンは3〜5個ならタブバー(Googleの目安。Appleは数の上限を決めず、収まらない分は「その他」のタブにまとまる)、多ければドロワー(このサイトの整理)。タブレット・PCは隠さずサイドナビにする(隠すナビゲーションは見つけにくい: NN group)。

8つのナビゲーション

アプリの主な場所
タブバー ↗
画面下部に常にあり、主な場所を切り替える(AppleのTab bar・GoogleのNavigation bar)
向くスマートフォンで、主な場所が3〜5個(Googleの目安。Appleは数を決めていない)
避ける6個以上・2個以下、画面の中の内容の切り替え
アプリの主な場所
ナビゲーションドロワー ↗
ボタン(≡)で一時的に開く、行き先の一覧。後ろの画面を覆う
向く狭い画面で、行き先が多くバーに収まらないとき
避ける広い画面(隠すと見つけにくい)
アプリの主な場所
サイドナビ ↗
画面の脇に常に表示する行き先の一覧(Appleのサイドバー・Googleのナビゲーションレール)
向くタブレット・PCなど広い画面
避けるスマートフォン(場所を取る)
1つ上の画面
アプリバー ↗
画面上部で、今の画面のタイトル・戻る・操作をまとめる
向く階層を1段ずつ下りるアプリで、戻り道とタイトルを示す
避ける主な場所の切り替え(タブバーを使う)
同じ画面の中
タブ ↗
同じ階層の関連する内容を、画面の中で切り替える
向く内容のまとまりが2〜5個ほどで、行き来する
避ける順番に読む内容、アプリ全体の移動
同じ画面の中
セグメントコントロール ↗
同じ内容の見せ方(地図/航空写真など)を、少ない選択肢から切り替える
向く表示の切り替えや絞り込みが2〜5個
避ける別々の内容のまとまり(タブを使う)
階層の中の今の位置
パンくずリスト ↗
サイトの階層の中で、今どこにいるかと上の階層へのリンクを示す
向く3階層以上のWebサイト
避ける浅いサイト、アプリ(戻るボタンが基本)
一覧の続き
ページネーション ↗
長い一覧を番号付きのページに分け、ページを行き来する
向く件数が多い一覧(検索結果・商品一覧)
避ける少ない一覧(「もっと見る」も検討)

移る範囲と画面の広さから選ぶ

したいことスマートフォンタブレット・PC
アプリの主な場所を切り替えるタブバー(3〜5個はGoogleの目安)。多ければナビゲーションドロワー(このサイトの整理)サイドナビ(常に表示)
1つ上の画面に戻る・今の画面のタイトルを示すアプリバー(戻る+タイトル)アプリバー。Webならパンくずリストも
同じ画面の中で、内容のまとまりを切り替えるタブタブ
同じ内容の見せ方を切り替えるセグメントコントロールセグメントコントロール
長い一覧の続きを見るページネーション(少なければ「もっと見る」)ページネーション
