セグメントコントロール

ボタンを横につなげて並べ、同じ場所の表示の仕方を切り替える部品だ。

Apple

AI解釈: スマートフォンでは5個までにそろえれば、AppleとGoogleのどちらにも沿う。6〜7個を並べられるのはAppleの広い画面だけなので、選択肢が増えそうならチップやメニューに切り替える。
⚠ 注記(Google/Material Design 3)

現行のM3(Expressive)ではセグメントボタンは推奨されず、代わりに接続ボタングループ(Connected button groups)を案内している。このページのGoogle欄は、既存の実装で使われているセグメントボタンの内容で、新しく作るときは接続ボタングループを使う(Google欄の参照ページ「後継: Connected button groups」)。

Appleでの、タブバーとセグメントコントロールの使い分け

Appleでは、どちらも横に並んだ選択肢に見えるが、役割がはっきり分かれている。iOS・iPadOSには画面の中のタブ(Tab view)がないため、画面の中で関係のある表示を切り替えるときは、セグメントコントロールを使う。

AI解釈 ― 総括

W3CとNN groupには、セグメントコントロールに当たる項目はない(W3Cは作るときの型、NN groupは用語の定義だけを「メモ」に載せている)。セグメントコントロールは、Appleが「表示(ビュー)の切り替え」を主な用途として説明するのに対し、Googleは「選択・表示切替・並べ替え」とやや広い用途で説明しており、両者で強調点が異なる。ラジオボタンと同じ「相互排他的な単一選択」を扱える点は共通している。

Googleのセグメントボタンには単一選択・複数選択の2つの公式バリアントがある。複数選択は、チェックボックスのように何も選ばない状態を含め任意の数を選べるもので、価格帯フィルタのような場面で使うとされている。

Appleは「iPhoneでは5個以下のセグメントに収めるべき」としており、Googleも「5個を超える場合はチップの使用を検討すべき」と明記している。両社とも独立に近い数値の上限を示している点は、実務上の目安として信頼度が高いと言える。

最も重要な点は、Material 3の表現力向上(Expressive)アップデート以降、セグメントボタン自体がGoogle公式に「推奨されない」コンポーネントになったことだ(詳しくはページ冒頭の注記を参照)。アクセシビリティについては、用途によって当てはめるARIAパターンが変わる(W3Cはセグメントコントロールを定めていないため、AI解釈)一方、Google自身の実装は表示切り替え用途でもTabsパターンではなくradiogroup/checkboxとして扱われるとしており、両者で考え方が異なる。

基本方針
セグメントコントロールは、地図アプリの「マップ/交通機関/航空写真」の切り替えのように、異なる表示(ビュー)を切り替える際によく使われるとしている。コントロール内の全セグメントは同じ幅を持ち、テキストまたは画像のどちらかを含められる。
セグメントボタンは、人々が選択肢を選んだり、表示を切り替えたり、要素を並べ替えたりするのを助けるコンポーネントで、アイコン・ラベルテキスト・またはその両方を含められるとしている。単一選択セグメントボタンは、複数のオプションから1つを選ぶ・ビューを切り替える・最大5つの要素を並べ替える場合に使うとしている(例: 飲料のサイズセレクター)。複数選択セグメントボタンは、選択が必須ではなく、何も選ばない状態も含め任意の数のオプションを同時に選べるとしている(例: レストラン検索の価格帯フィルタ)。

例外・許容ケース
セグメントが多すぎると読み取りにくく操作に時間がかかるため、広い画面では約5〜7個まで、iPhoneでは約5個までを目安にするとしている。全セグメントの幅が同じであるため、内容量が一部のセグメントだけ多い/少ないと見た目が崩れるとして、内容量を揃えることを推奨している。1つのコントロール内でテキストと画像を混在させることも、一貫性を欠き分かりにくくなるため避けるべきとしている。
1つのセグメントボタンに5個を超えるセグメントを使うべきではなく、選択肢が5個を超える場合はチップなど別のコンポーネントの使用を検討すべきとしている。セグメントボタンは、ビューポートやフレームの端から十分な余白を確保すべきで、大きな画面幅いっぱいに広げることは避けるべきとしている(ラベル周りの余白が大きくなりすぎて使い勝手が悪化するため)。

メモ

単一選択 / 複数選択: セグメントボタンには2つの公式バリアントがある。単一選択はラジオボタンのように一度に1つだけ選択でき、複数選択はチェックボックスのように複数(またはゼロ)を選択できる。M2では「トグルボタン」という名称だったが、M3でこの2バリアントを持つ「セグメントボタン」として刷新された。

メモ

作るときの型(AI解釈): W3Cはセグメントコントロールという部品を定めていない。フォームの中で1つの値を選ぶ用途ならRadio Groupパターン(radiogroup/radio)、表示する内容を切り替える用途ならTabsパターン(tablist/tab/tabpanel)が近い。いずれも、名前・役割・状態が支援技術に伝わることが求められる(4.1.2)。Google自身の実装は、表示の切り替えでもradiogroup/checkboxとして扱うとしている。

メモ

用語集の定義: UI Elements Glossaryでは「Segmented Button(Segmented Control)」を、同じデータの見せ方の切り替えや、内容の絞り込みに使う、ボタンがつながった部品として定義している。設計の指針を述べた専用の記事はない。
