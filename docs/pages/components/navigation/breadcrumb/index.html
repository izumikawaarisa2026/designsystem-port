コンポーネント / パンくずリストSPEC No. 017

パンくずリスト

サイトの階層の中で今いる場所を、上の階層からの道筋で示すリンクの並び

コンポーネントイメージ(共通形状)
ホーム>デザイン>コンポーネント

現在ページの親ページへのリンクを階層順に並べる。この例では、NN groupの推奨どおり現在ページ(最後の項目)をリンクにしていない。

目的・役割
今の場所を示し、上の階層へ1回で戻れるようにする
よく使われる場面
ネットショップの「ホーム > 家電 > 冷蔵庫」、ヘルプサイトの記事の上部
似たコンポーネント
主な場所を切り替えるのはナビゲーションバー。パンくずは補助の案内

まず押さえる要点

  1. 1
    閲覧の履歴ではなく、サイトの階層を見せる
    NN group
  2. 2
    今いるページはリンクにしない
    NN group。W3CのAPGの作り方の1つ
  3. 3
    アプリでは戻るボタンが基本
    Apple・Googleに専用のコンポーネントはない
    Apple・Google
  4. 4
    リンクの文字は4.5:1以上
    W3C 1.4.3

意見が分かれる点

同じ問いに対して、系列によって答えが違う点。図は概念図。

今いるページ(末尾の項目)を、リンクにする?
W3C(APG)
どちらの作りも認めている。リンクにするならaria-current="page"を付ける。リンクにしなければaria-currentは任意
NN group
リンクにしない。何も起きないリンクは置かないため。リンクの項目とは見た目でも区別する
AI解釈: 今いるページはリンクにせず文字だけにし、「現在のページ」と分かるようにすると、NN groupの勧めに沿い、W3CのAPGの作り方の1つにも当たる。APGは実装の参考例で、適合の要件ではない。

四系列デザインシステム比較

AI解釈 ― 総括

AppleとGoogleには、パンくずリストに当たる専用のコンポーネントはない(Appleは、階層を戻るボタンで行き来するのが基本)。専用の内容を持つのは、W3C(WAI-ARIA)とNielsen Norman Groupの2系列だ。

Nielsen Norman Groupが示す最も重要な原則は、ユーザーの閲覧履歴ではなく、サイトの階層構造そのものを表示すべきという点だ。ブラウザの「戻る」履歴とパンくずリストは似ているようで役割が異なり、パンくずリストは常に同じサイト構造を反映すべきものだ。

W3Cの実装パターン(nav要素 + 順序リスト + 現在ページへのaria-current="page")と、NN groupの「先頭は必ずホームページへのリンクにする」という原則は、モバイルでの短縮表示(末尾の階層だけを表示する)という現実的な要請と緊張関係にある点も見逃せない。画面幅に応じてどちらを優先するかは、実装側の判断が必要になる。

基本方針
該当なし。iOSは階層の遷移を、上部のツールバーの戻るボタンで扱うのが基本(HIG Toolbars)。近いコンポーネントとして、macOSにはPath controls(Finderのパスバーのように、階層の中の位置を並べて示すコンポーネント。iOSなどでは使えない)がある。
該当なし(M3のコンポーネントの一覧にBreadcrumbsはない)
今のページの親ページへのリンクを、階層の順に並べたリスト。ナビゲーションのランドマーク(nav要素。aria-labelかaria-labelledbyでラベルを付ける)として作り、リンクは順序リスト(ol)で並べる。多くはページ本文の直前に横に置く。
サイトの階層での現在位置を示す補助のナビゲーションで、グローバルナビゲーションバーやローカルナビゲーションを補うものであり、代わりにはならない。最も重要なのは、閲覧の履歴(たどってきた順)ではなく、サイトの階層そのものを表示すること。
例外・許容ケース
該当なし
該当なし
APGは、今のページをリンクにする作りも、しない作りも認める(リンクならaria-current="page"を付け、リンクでなければ任意)。リンクにしないのはNN groupの推奨。キーボード操作が「適用なし(Not applicable)」なのは、普通のリンクの並びで特別なキー操作が要らないため。
1〜2階層しかない浅いサイトでは不要。親が複数あるページ(ポリヒエラルキー)では、代表的な経路を1つだけ示す。モバイルでは複数行に折り返さず、押せる範囲が小さすぎたり項目が密集しすぎたりしないようにする。画面が狭ければ末尾の階層だけを出す短縮もできるが、「いつもホームへのリンクから始める」原則とはぶつかる。
アクセシビリティ(WCAG基準)
該当なし
該当なし
堅牢(Robust)・知覚可能(Perceivable) ― nav要素によるランドマーク(支援技術がページ内を移動しやすくする)、aria-current="page"による現在位置の明示が中心。区切り記号(> や / など)は装飾で、支援技術に読み上げさせる必要はない。
根拠となる原則 ― 適合区分ではなく、サイトの構造の理解を助ける使い分けの指針。モバイルの押せる範囲(約1×1cm)は、ほかのコンポーネントと共通の目安。
