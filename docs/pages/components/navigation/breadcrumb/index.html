コンポーネント / パンくずリストSPEC No. 017

パンくずリスト

サイトの階層の中で今いる場所を、上の階層からの道筋で示すリンクの並びだ。

コンポーネントイメージ(共通形状)
ホーム>デザイン>コンポーネント

現在ページの親ページへのリンクを階層順に並べる。この例では、NN groupの推奨どおり現在ページ(最後の項目)をリンクにしていない。

目的・役割
今の場所を示し、上の階層へ1回で戻れるようにする
よく使われる場面
ネットショップの「ホーム > 家電 > 冷蔵庫」、ヘルプサイトの記事の上部
似た部品との違い
主な場所を切り替えるのはナビゲーションバー。パンくずは補助の案内

意見が分かれる点

同じ問いに対して、系列によって答えが違う点です。図は概念図です。

今いるページ(末尾の項目)を、リンクにする?
W3C(APG)
どちらの作りも認めている。リンクにするならaria-current="page"を付ける。リンクにしなければaria-currentは任意
NN group
リンクにしない。何も起きないリンクは置かないため。リンクの項目とは見た目でも区別する
AI解釈: 今いるページはリンクにせず文字だけにし、「現在のページ」と分かるようにすると、NN groupの勧めに沿い、W3CのAPGの作り方の1つにも当たる。APGは実装の参考例で、適合の要件ではない。

四系列デザインシステム比較

AI解釈 ― 総括

AppleとGoogleには、パンくずリストに当たる専用の部品はない(Appleは、階層を戻るボタンで行き来するのが基本)。専用の内容を持つのは、W3C(WAI-ARIA)とNielsen Norman Groupの2系列だ。

Nielsen Norman Groupが示す最も重要な原則は、ユーザーの閲覧履歴ではなく、サイトの階層構造そのものを表示すべきという点だ。ブラウザの「戻る」履歴とパンくずリストは似ているようで役割が異なり、パンくずリストは常に同じサイト構造を反映すべきものだ。

W3Cの実装パターン(nav要素 + 順序リスト + 現在ページへのaria-current="page")と、NN groupの「先頭は必ずホームページへのリンクにする」という原則は、モバイルでの短縮表示(末尾の階層だけを表示する)という現実的な要請と緊張関係にある点も見逃せない。画面幅に応じてどちらを優先するかは、実装側の判断が必要になる。

基本方針
該当なし。iOSは階層の移動を、上部のツールバーの戻るボタンで扱うのが基本(HIG Toolbars)。近い部品として、macOSにはPath controls(Finderのパスバーのように、階層の中の位置を並べて示す部品。iOSなどでは使えない)がある。
該当なし(M3の部品の一覧にBreadcrumbsはない)
パンくずリストは、現在ページの親ページへのリンクを階層順に並べたリストと定義されている。ナビゲーションのランドマーク領域(nav要素、aria-labelまたはaria-labelledbyでラベル付け)として実装し、リンクの並びは順序リスト(ol)で構成すべきとしている。多くの場合、ページ本文の直前に水平に配置される。
パンくずリストは、サイトの階層構造上の現在位置を示す補助的なナビゲーションであり、グローバルナビゲーションバーやローカルナビゲーションを補完するものであって、それらの代わりにはならないとしている。最も重要な原則は、ユーザーの閲覧履歴(たどってきた順序)ではなく、サイトの階層構造そのものを表示すべきという点。
例外・許容ケース
該当なし
該当なし
APGは、現在のページをリンクにする作りも、リンクにしない作りも認めている(リンクにするならaria-current="page"を付け、リンクでなければaria-currentは任意)。現在のページをリンクにしないのは、NN groupの推奨。キーボード操作が「適用なし(Not applicable)」とされているのは、パンくずリストが普通のリンクの並びで、特別なキー操作がいらないため。
1〜2階層しかない「浅い」サイト構造ではパンくずリストは不要としている。複数の親を持つページ(ポリヒエラルキー)では、1つの代表的な経路だけを示すべきとしている。モバイルでは複数行に折り返してはならず、タップ領域が小さすぎたり項目が密集しすぎたりしないよう注意すべきとしている。画面が狭い場合は末尾の階層だけを表示する短縮も検討できるが、これは「常にホームページへのリンクから始めるべき」という原則とは緊張関係にある点に注意が必要。
アクセシビリティ(WCAG基準)
該当なし
該当なし
堅牢(Robust)・知覚可能(Perceivable) ― nav要素によるランドマーク(支援技術がページ内を移動しやすくする)、aria-current="page"による現在位置の明示が中心。区切り記号(> や / など)は装飾であり、支援技術に読み上げさせる必要がない点にも注意が必要。
根拠となる原則 ― POURのような適合区分ではなく、サイト構造の理解を助けるという使い分けの指針。ただしモバイルでのタップ領域(約1×1cm)は、他のコンポーネントと共通するアクセシビリティ上の目安として関わる。
