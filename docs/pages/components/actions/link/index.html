コンポーネント / リンクSPEC No. 003

リンク

押すと別のページや同じページの別の場所へ移動する、文字の部品だ。

まず押さえる要点

  1. 1
    移動はリンク、処理の実行はボタン
    役割で使い分ける
    このサイトの整理(サマリーの「似た部品との違い」)
  2. 2
    文章の中のリンクは色と下線
    両方あるのが最も分かりやすい
    NN group
  3. 3
    下線を省くなら差を確かめる
    周りの文字と3:1以上
    W3C 1.4.1・G183
  4. 4
    文言に行き先を入れる
    「詳しく見る」だけにしない
    Apple。W3C 2.4.4

◯ 良い例

詳しくは料金プランの比較をご覧ください。

本文の中のリンクに色と下線の両方があり、ひと目でリンクと分かる。

✕ 悪い例

詳しくは料金プランの比較をご覧ください。

色だけで示し、周りの文字(#2E3457)との明るさの差が1.83:1で3:1に届かない。リンクと気づきにくい。

根拠: NN group(色と下線の両方があるのが最も分かりやすい)、W3C 1.4.1・G183(色だけで見分けさせるなら、周りの文字と3:1以上)。比はこのサイトで計算した値。

下線を必ず付けるかは系列で違う(NN groupも必須とはしていない)。悪い例は、下線がないことではなく、色の差が足りないことを示している。

意見が分かれる点

同じ問いに対して、系列によって答えが違う点。図は概念図。

リンクに下線は必要?
NN group
色と下線の両方が最も分かりやすい。ナビゲーションのようにリンクの集まりと分かる場所だけ省いてよい。2026年3月の編注で、下線は必須ではないとした
W3C
下線は求めていない。ただし色だけで見分けさせる場合は、周りの文字と3:1以上の明度の差が必要(1.4.1・G183)。下線を付けるのがいちばん確実
Apple
リンク専用の決まりはなく、全体の方針として、色だけに頼らず形やアイコンなどの手がかりを足すよう求めている
AI解釈: 文章の中のリンクは下線を付け、ナビゲーションやメニューのようにリンクと分かる場所だけ省く、という使い分けなら3系列のどれとも食い違わない。下線をなくす場合は、周りの文字との3:1の差を確かめる。
リンクの文言だけで行き先が分かる必要がある?
Apple
「ここをタップ」のような曖昧な文言は避け、「◯◯について詳しく見る」のように行き先や機能が分かる言葉にする
W3C
レベルA(2.4.4)では、同じ文や段落などの文脈と合わせて分かればよい。レベルAAA(2.4.9)では、リンクの文言だけで分かる必要がある
AI解釈: 「詳しく見る」だけでも、すぐ前の見出しや文と合わせて分かればW3CのAAは満たせる。ただし読み上げソフトでリンクだけを一覧にすると区別がつかなくなるため、Appleの勧めるように行き先を入れた文言にしておくのが安全だ。

AI解釈 ― 総括

リンクには、ボタンのような数値の基準がない。代わりにApple・WCAG・NN groupは、「色だけに頼らず見分けられるか」と「文言だけで目的が伝わるか」という2つの観点で考え方を示している。

Googleには独立した「Link」コンポーネントはなく、「Text button」(ラベルのみ・枠なしの低優先度ボタン)が最も近い相当物だ。厳密なハイパーリンクとは別物だが、見た目の軽さという点では近い存在と言える。

実務では色+下線を基本にし、ナビゲーションのように文脈で明らかな場合だけ下線を省くのが、いちばん確実な着地点だ。WCAG 1.4.1は「色だけで見分けさせない」ことを求めていて、色だけで区別するなら周りの文字と3:1以上の明度差が必要だ(G183)。Nielsen Norman Groupも2026年3月の編注で、下線は必須ではなく、コントラストにホバー時・フォーカス時の手がかりを組み合わせる方法もあるとし、記事の見た目の推奨は出発点として扱うよう補足している。

基本方針
独立した「リンク」ページは持たず、ライティングとアクセシビリティの各ページに分けて言及している。リンクのラベルには動詞を使い、「ここをタップ」のような曖昧な文言を避け、「◯◯について詳しく見る」のように具体的な行き先や機能を示す言葉を使うべきとしている。文中のリンクに矢印を付けるかどうかは定めていない(リストの行の右端の矢印「›」は、階層の次の画面へ移る印(disclosure indicator)として、リンクとは別に定めている)。
該当なし(独立した「Link」コンポーネントはない)。参考: Materialには2014年の初代デザイン(当時は「Flat button」)から続く「Text button」という考え方があり、ラベルのみ・枠や塗りの背景を持たない、最も優先度が低いアクションに使う表現として定義されている。ダイアログやカードの中の軽い操作など、見た目の重さを抑えたい場面で使われる。
2.4.4(レベルA)は、リンクの目的がリンクテキスト単体、またはリンクテキストと周囲の文脈から判別できることを求める。より厳格な2.4.9(レベルAAA)は、リンクテキスト単体だけで目的が分かることを求める。1.4.1(レベルA)は、色だけをリンクの識別手段にしてはならないと規定する。3.2.4(レベルAA)は、ページをまたいで繰り返し出てくる同じ働きの部品を、一貫して識別できるようにすることを求める。全ページ共通のナビゲーションやフッターのリンクに、ページごとに違う名前を付けないことが基本。ただし文言が完全に同じである必要はなく、5ページ目から見た「4ページ目」へのリンクを「前のページ」と呼ぶような、文脈に合わせた違いは認められる。
記事の本文は、リンクだと分かる「見た目上の手がかり」を最大化するには、リンクテキストに色と下線の両方を付けるとよいとしている。また、訪問済みリンクと未訪問リンクは彩度の異なる同系色で区別し、未訪問側をより鮮やかにすることを推奨している。
例外・許容ケース
色による区別についても直接のリンク基準ではなく、アクセシビリティ全般の方針として「色だけに頼らず、形やアイコンなど視覚的な手がかりを追加する」ことを求めている。数値的な例外規定はない。
「Text button」はあくまでボタン(操作)の一種であり、文中に埋め込む本来のハイパーリンクとは位置づけが異なる。この点を踏まえ、厳密な意味での「リンク」の独立ガイダンスは見当たらない、という理解が正確。
2.4.4は、リンクの文言だけで、または同じ文・段落などの文脈と合わせて目的が分かればよい。例外は、ページ上の情報だけでは誰にとっても目的が分からないリンク(その場合は求められない)。1.4.1は、色だけでリンクを見分けさせないこと。色だけで区別するなら、周りの文字と3:1以上の明度の差が必要になる(テクニックG183)。いちばん確実なのは下線を付けること。
ナビゲーションメニューなど、リンクの集まりであることが明確な領域に限り、下線を省略してもよいとする例外がある。ただし赤や緑など色覚異常の影響を受けやすい色を使う場合や、低視力ユーザーへの配慮を優先する場合は、下線を必ず残すべきとしている。2026年3月の編注では、下線は必須ではなく、周りの文字とのコントラストにホバー時・フォーカス時の手がかりを組み合わせれば1.4.1を満たせる(G183)と補足し、記事の見た目の推奨は出発点として扱うよう書いている。なお、現在のW3CのG183(WCAG 2.2版)の確認手順は「周りの文字と3:1以上」の1つだけで、ホバー/フォーカス時の手がかりは以前の版にあった条件。
