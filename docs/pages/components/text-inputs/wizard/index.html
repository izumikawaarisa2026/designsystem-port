ウィザード(ステップ形式の入力)

入力の手順をいくつかのステップに分け、1つずつ順に進めてもらう形だ。

コンポーネントイメージ(共通形状)
✓お届け先2支払い方法3確認
支払い方法(ステップ2/3)
← お届け先に戻る確認へ進む

全体のステップと今の位置を示し、次にすることが分かる名前のボタンで進む。

目的・役割
長く複雑な入力を小さなまとまりに分け、迷わず最後まで進めるようにする
よく使われる場面
会員登録、購入手続き(お届け先→支払い→確認)、アプリの初期設定
似た部品との違い
1画面で済む入力はテキストフィールドなどを並べたフォーム、1つの作業を全画面で行うのはフルスクリーンダイアログ

意見が分かれる点

同じ問いに対して、系列によって答えが違う点です。図は概念図です。

複数ステップの作業は、モーダルで出してよい?
Apple
コンテンツの編集のような複数ステップの作業には、全画面のモーダルを検討できる。ただし、モーダルの作業は単純・短く保つ
✓ ステップ1▶ ステップ2・ステップ3
NN group
複数ステップのモーダルは、元の作業から離れる時間を延ばすだけ。最初から複数ステップが必要なら、モーダルではない普通のページを割り当てる
AI解釈: 写真の編集のように、元の画面を見る必要がなく、短く終わる作業なら全画面のモーダルでもよく(Apple)、会員登録や購入のように長く、途中で別の画面を確かめたくなる手順は、普通のページで進める(NN group)と考えると両立する。
ステップは、好きな順に進めてよい?
✓✓3
Google(M1)
順に終えないと進めない型(linear)と、好きな順に入れられる型(non-linear)の両方を用意している
✓ ステップ1▶ ステップ2・ステップ3
NN group
順番をはっきりさせ、前のステップを終えるまで先に進ませない。好きな順に進められる利点が大きいなら、そもそもウィザードに向かない
AI解釈: 前の入力で次の内容が変わる手順は、順に進める形にする(両者とも一致)。順番に意味がない入力なら、ステップに分けずに1つのフォームや、見出しで区切ったページにするほうが、NN groupの考え方に合う。Googleのnon-linearは、現行M3にはないM1の参考情報だ。

四系列デザインシステム比較

AI解釈 ― 総括

ウィザード専用の部品を、現行のガイドラインとして持つ系列はない。Appleは全画面のモーダルの中で扱い、GoogleはMaterial Design 1にStepperがあったが現行のM3にはない。最も具体的なのはNN groupの記事と、W3Cの複数ページのフォームのチュートリアルだ。

共通しているのは、全体のステップ数と今の位置を示すことだ。NN groupはステップの一覧や図で今のステップを強調するよう求め、W3Cは最初に全体の数を伝え、見出しやtitleに「ステップ2/4」と入れることを勧めている。また、途中で中断しても作業を失わないようにすることも、Apple・W3C・NN groupの3系列が触れている(閉じる前の確認・制限時間の延長・途中保存)。

W3Cの3.3.7(冗長な入力)は、同じ手続きの中で前に入力した情報をもう一度入力させないことを求める、ウィザードに直接関わる要件だ(例外あり)。モーダルで出すかどうかと、好きな順に進めてよいかは、系列で意見が分かれる(「意見が分かれる点」を参照)。

基本方針
複数ステップの作業(文書への書き込み・写真の編集など)には、気が散りにくい全画面のモーダルを使うことを検討できるとしている。一方で、モーダルの作業は単純・短く・すっきりと保つよう求めている(複雑すぎると、中断した元の作業を見失うため)。
手順を番号付きのステップに分けて、進み具合を示す。ある入力によって次の入力が決まる場合に使う。短いフォームを区切るために使ったり、1ページに複数置いたり、入れ子にしたりしない。
長いフォームは、論理的なまとまりごとの小さなフォームに分けると、取り組みやすく分かりやすくなる(特に、操作に慣れていない人や認知障害のある人)としている。同じ手続きの中で、前に入力した情報をもう一度入力させない(3.3.7・レベルA。自動で入れるか、選べるようにする。例外あり)。
慣れていない人や、たまにしか行わない作業(設定・セットアップなど)に向く。1ページの情報が少なくなり、間違いが減る。分岐によって、その人に関係のあるステップだけを見せられる。繰り返し使う人には、別の速い方法も用意する。
進み具合と現在地
モーダルに入ると元の場所から離れるため、作業名をタイトルに書き、必要なら説明を添えて、今どこで何をしているかを分かるようにする。
画面の幅に合わせて、横型(前のステップの内容で次が決まる場合)と縦型(狭い画面向け)を使い分ける。モバイルでは、ステップを文字・点・プログレスバーで示し、ステップが多いときや途中で増えるときはプログレスバーにする。
最初のステップで全部で何ステップあるかを伝え、各ステップで進み具合を伝える。ページのtitleと見出しに「ステップ2/4」のように入れる。ステップ数が決まっていれば、手順の一覧(順序付きリスト)で、完了・現在のステップを支援技術にも分かるように示す。
ステップの一覧や図を出し、今のステップを強調して、全体の流れと長さが分かるようにする。
順番・戻る
モーダルの中に画面の階層を作ると、戻り方が分からなくなるとしている。サブビューが必要なら、たどる道を1本にし、閉じるボタンと間違えるようなボタンを置かない。
順に終えないと進めない型(linear)に加え、好きな順に入れられる型(non-linear)もある。順に進む流れの中の任意のステップは、「任意」と示す。
任意のステップは分かるようにし、飛ばせるようにする。全体の説明は各ページで繰り返す。
順番をはっきりさせ、前のステップを終えるまで先に進ませない(好きな順に進められる利点が大きいなら、ウィザードに向かない)。「次へ」「戻る」のボタンを置き、ボタンには次にすることが分かる名前を付ける。
中断・保存
閉じる手段を常に分かるようにする。閉じると作った内容が失われる場合は、事情を説明し、保存などの解決策を示す。
後から戻って直せる「編集できるステップ」と、終えたら直せない「編集できないステップ」がある。ステップの保存に時間がかかる場合は、保存後に短い知らせを出してよい。
できれば制限時間を設けない。設ける場合は、延長・調整できるようにする(2.2.1)。
途中で抜けて状態を保存し、後で再開できるようにする。各ステップは、ほかの場所や前のステップの情報を必要としないようにする。

ユースケース
  • 写真の編集のような複数ステップの作業を、全画面のモーダルで集中して行う
  • 画面の中の道筋は1本にし、閉じる手段を常に見せる
  • 前の入力で次の入力が決まる手順に、番号付きのステップを使う
  • 短いフォームの区切りには使わない
  • 最初に全体のステップ数を伝え、ページの見出しとtitleに「ステップ2/4」を入れる
  • 前のステップで入力した情報は、自動で入れるか選べるようにする(3.3.7)
  • 設定・セットアップのような、たまにしか行わない作業に使う
  • ヘルプや説明は、ウィザードを覆わない位置に出す
  • 前回の選択を、次回の初期値に使う
