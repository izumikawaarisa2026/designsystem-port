原則と土台(ファウンデーション)の違い

デザインシステムは、おおまかに原則 → 土台 → コンポーネントの3段で組み立てられている。思想レイヤーが「原則」を、このレイヤーが「土台」を比べる。このサイトでは、特定のコンポーネントに限らず多くのコンポーネントに共通して効く決まり(色・文字・文章・アイコン・余白・形・影・画面の広さへの対応、動き・音・入力)を「土台」と呼んでいる。

なぜ土台を比べるのか

コンポーネントの見た目や数値の違いの多くは、土台の違いから来ている(例: ボタンの角丸の違いはシェイプの決まりの違い)。土台を先に知っておくと、コンポーネントページの比較が「なぜそう違うのか」まで読める。

ただし、土台を持つのはAppleとGoogleだけだ。W3CとNN groupは土台を持たないため、各トークンページでは、W3Cは「そのトピックに関わる達成基準」、NN groupは「そのトピックの記事(調査に基づく指針)」を比べている。

AI解釈 ― 総括

以降の各トークンページ(カラー・タイポグラフィ等)を読む際は、「4系列が同じ棚に同じものを並べている」という前提を持たないことが重要だ(理由は以下のとおり)。この比較サイトのファウンデーション9ページ・インタラクション3ページという区切り方自体が、Apple・Googleの実際の構成を主な参考にした編集上の判断であることを踏まえて読む。

最も大きな点は、Google(Material Design 3)が「Foundations」と「Styles」を明確に別のトップレベルセクションとして分離していることだ。色・タイポグラフィ・シェイプ・モーションといった視覚的なトークンはStyles側に属し、Foundations側にはAccessible design・Adaptive design・Content design・Design tokensなど機能横断的な考え方が集められている。本サイトの「Foundation」という1つの括りは、Googleの実際の区分ではFoundationsとStylesという2つの異なるセクションにまたがっていることになる。

一方Appleは、AccessibilityもColorもTypographyもWritingも、Foundations配下のトピックとして区別なく並べており、Googleのような二分はしていない。ただしAppleはFoundationsの外に、Patterns(よくある操作の流れ)・Inputs(入力手段)・Technologies(Apple固有の技術)を並列の区分として持ち、設計原則(Design principles)もFoundationsではなくGetting startedに置いている。Googleは原則もFoundationsの中に置いているため、「原則」「入力」「体験パターン」を基礎と同じ箱に入れるか、別の箱に分けるかが2系列の構造上の違い(下部の「Foundationsと並列の区分」参照)。

W3C(WCAG)とNielsen Norman Groupは、土台(Foundations)を持たない。WCAGのPOURの4原則は「原則」に当たり(思想レイヤーで扱う)、土台の各トピックには、色のコントラストや文字の拡大などの達成基準が「満たすべき条件」として個別に関わる。NN groupは記事をTopicsで分類しているが、値をそろえる仕組みではなく、調査に基づく指針として読む。

基本方針
Foundationsには、Accessibility・Color・Typography・Layout・Writingなどのトピックが、「見た目のトークンか横断のルールか」の区別なく、アルファベット順に同じ階層で並ぶ。Googleのような「Foundations」と「Styles」の二分はない。HIG全体は6つの区分に分かれ、Foundationsの外に、よくある操作の流れのPatterns、入力手段のInputs、Apple固有の技術のTechnologiesが並ぶ。
M3のサイトは、Foundations・Styles・Components・Develop(実装)に分かれる。Foundationsには原則・アクセシビリティ・レイアウト・操作(Interaction)・文章など横断的な考え方が集まり、色・タイポグラフィ・シェイプ・モーション・エレベーション・アイコン・余白といった見た目のトークンはStylesに属する。設計の原則(principles)もFoundationsの中(Overview)にある。
WCAGは色の値や文字サイズの体系ではなく、「できあがった画面が満たす条件」を定める。そのため、Apple・Googleの土台のように色・文字・余白をそろえる仕組み(トークン)はない。代わりに、色のコントラストや文字の拡大など、各トピックの最低限の条件が個別の達成基準として散らばる。各ページのW3Cの欄は、この「トピックに関わる達成基準」を比べている。
Apple・Googleのような実装者向けのデザインシステムではなく、ユーザビリティ調査にもとづく記事・レポートの集まり。記事は「Topics」(Visual Design・Writing for the Webなど)で整理されるが、色・文字の値をそろえる土台はない。各記事は、調査にもとづく原則や指針として読む。
本サイトの分類との関係
このサイトの「Foundation」(9ページ)と「Interaction」(3ページ)は、AppleのFoundations(色・文字・レイアウトなど)とInputs(入力方法・ジェスチャー)の2区分にまたがる。「ローディング」「モーダル」のようなAppleのPatternsの一部は、このサイトではコンポーネントのページで扱う。
このサイトの「Foundation」という1つの括りは、Googleでは FoundationsとStylesの2つのセクションにまたがる(Googleの構造をそのまま踏襲していない)。レイアウトはStylesではなくFoundations側にある。
POURの4原則は「原則」に当たり、思想レイヤーの「アクセシビリティ」ページで扱う。このページでは、土台の各トピックに関わる達成基準(左の一覧)として位置づける。
NN groupに専用の記事がないトピックは、各トークンページのNN group欄に「専用記事なし」と書いている。
アクセシビリティの位置づけ
AccessibilityはFoundationsの1トピックで、ほかの見た目のトークン(Color・Typographyなど)と同格に並ぶ。「横断の前提条件」より「並列の1トピック」に近い。
アクセシビリティはFoundationsの複数の区分(Overviewの支援技術、Building for all、Designingの色のコントラストなど)に分かれて置かれ、1トピックより横断の前提条件に近い。
WCAGにとってはアクセシビリティが文書全体の目的そのもので、「土台の中の1トピック」という位置づけにはならない。
アクセシビリティの記事はあるが、Foundationsのような包括的な体系にはなっていない。
