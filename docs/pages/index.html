DesignSystem Port

(サイト名は仮称です)

Apple(Human Interface Guidelines)/ Google(Material Design 3)/ W3C(WCAG)/ Nielsen Norman Groupという、UI/UXの主要なガイドラインを横断的に集約し、AIの独自解釈を加えて比較するサイトです。

このサイトについて(思想)

単なる情報の転載サイトではありません。同じ「ボタンの押せる範囲」でも、系列ごとに数値や考え方が違います。その違いを一目で比較でき、そこに「総合するとこうだが、実務上はこう」というAIの統合見解が乗っている、という点が価値の核です。

各系列の文章はそのまま転載せず、要約・独自解釈・言い換えのみを行い、必ず公式ページへのリンクを添えています。原文はリンク先で確認してください。

また、一度作って終わりの静的なページにはせず、内容を定期的に見直し続けることを前提としています(詳しくは下部の「運用ルール」)。

対象の4系列

各ページは、次のサイトを一次情報として読み、要約・言い換えで比べています。原文は各ページの「参照ページ(公式)」のリンク先で読めます。

Apple
Human Interface Guidelines(HIG)

Apple製品の公式デザインガイドライン。

参考にしているサイト
  • Human Interface Guidelines ↗
    Appleの各プラットフォームに共通する設計の原則と、コンポーネント・パターンごとの指針。
このサイトでの扱い

iOS・iPadOS・macOS・watchOSの内容を載せる(tvOS・visionOSは対象外)。

Google
Material Design 3(M3)

Android・Webを中心としたGoogleの公式デザインシステム。

参考にしているサイト
  • Material Design 3 ↗
    現行のMaterial Design。コンポーネントごとの使い方・寸法・トークンを載せている。
  • Material Design 2(旧版) ↗
    1つ前の版。M3にページがない項目(表・音など)の参考にする。
  • Android Developers ↗
    Androidアプリの開発者向けの公式ドキュメント。トーストやウィジェットなど、OSの機能の説明に使う。
このサイトでの扱い

M3を優先する。M3にページがない項目だけ、旧版(M2・M1)やAndroid Developersを使い、そのことを書き添える。

W3C
WCAG 2.2・WAI-ARIA・APG

Webアクセシビリティの国際標準(WCAG)と関連する文書。

参考にしているサイト
  • WCAG 2.2 ↗
    Webアクセシビリティの達成基準そのもの(規格の本文)。
  • Understanding WCAG 2.2(解説書) ↗
    達成基準ごとに、意図・具体例・例外を説明するW3Cの解説書。
  • ARIA Authoring Practices Guide(APG) ↗
    メニューやタブなど、よく使うコンポーネントの役割や状態を支援技術に伝える作り方の例(要件ではない)。
このサイトでの扱い

達成基準は適合の要件として扱う。APGやチュートリアルは実装の参考例で、要件ではない。MDNは「解説」として補足に置く。

Nielsen Norman Group
記事・用語集(UXリサーチ)

特定の製品に属さない、独立系のユーザビリティ研究機関。

参考にしているサイト
  • Articles ↗
    ユーザビリティ調査にもとづく記事の一覧。各ページの根拠の多くはここにある。
  • UI Elements Glossary ↗
    UIの要素の名前と意味を短く説明する用語集。
このサイトでの扱い

調査にもとづく設計の根拠として扱う(適合の基準ではない)。数値は記事に書かれているときだけ載せる。

サイトの読み方

読む順番

初めての方は、次の順に読むと全体がつかみやすくなります。

  1. 原則比較 ― 4系列がそれぞれ何を大事にしているか(根本の考え方)。アクセシビリティもここに入ります。
  2. ファウンデーションの思想比較 ― 色・文字・余白など、どのコンポーネントにも効く土台の分け方。そこからカラーなどの各ページへ。
  3. 各コンポーネントのページ ― グループごとの入口から読むと、似たコンポーネントの違いが分かります(ボタン/Selectionの選び方/オーバーレイの使い分け/情報伝達の使い分け)。
  4. タグから見る ― エラー処理・通知など、作業の場面からページを探せます。

コンポーネントを選びたいときの近道

どのコンポーネントを使うか迷ったときは、次の4つの使い分けのページから入ると、似たコンポーネントの違いをまとめて比べられます。

  • Selectionの選び方 ― チェックボックス・ラジオボタン・トグルスイッチ・チップなど、値や項目を選ぶコンポーネント
  • タブとセグメントの使い分け ― 見た目が似ている、表示を切り替える2つのコンポーネント
  • オーバーレイの使い分け ― ダイアログ・シート・ドロワー・メニューなど、画面の上に重ねて出すコンポーネント
  • 情報伝達の使い分け ― バナー・スナックバー・トースト・ツールチップなど、利用者に知らせるコンポーネント

各コンポーネントのページの構成

各コンポーネントのページは、上から次の順に並んでいます。

サマリー
タイトルの下の1文と、コンポーネントのイメージ図・目的と役割・よく使われる場面・似たコンポーネントの表。
意見が分かれる点
4系列で答えが違う論点。サイズなど図にできるものは図で示す(系列の意見が分かれていないページにはない)。
四系列デザインシステム比較
見出しの下に「AI解釈 ― 総括」(4系列の違いを統合したAIの見解。太字が結論)。続けて、スマートフォンでは系列ごとのカード、PCでは項目を行・系列を列にした比較表。図(デザインイメージ)が先頭。
図の色
図やカードの色(Apple=オレンジ・Google=ティール・W3C=ゴールド・NN group=紫)は、系列を見分けるための色で、各社の実際の配色ではない。図はすべて概念図。
マーカー
若草色の下線が付いた太字は、総括で取り上げている違い・共通点。
メモ
用語の説明や、1系列だけの補足。
参照ページ(公式)
その内容を確かめられる公式のページ。公式で別のページ・節に分かれている内容は、それぞれリンクする。
関連するページ
ページの末尾に、関係するコンポーネントやトピックのページを、名前と1文の説明のカードで並べる。節の多い長いページには、上部に「このページの内容」(目次)もある。
タグ
原則タグ(POUR)とプロセスタグ(12のくくり)。押すと「タグから見る」で同じタグのページを一覧できる。

単位の関係(pt・dp・px)

3つとも、画面の細かさ(密度)に左右されない「論理的な単位」です。ただし定義と基準の密度がそれぞれ違うため、数値をそのまま換算できる単位ではありません。スマートフォンの画面では、1pt・1dp・1pxがおおむね近い大きさで描かれるので、このサイトではおおよその大きさを並べて比べる目安として扱います(AI解釈)。

単位使う系列基準実際のピクセルとの関係出典
pt(ポイント)Apple@1xの画面で1pt=1ピクセル@2xの画面では2ピクセル、@3xでは3ピクセルHIG Images ― Resolution ↗
dp(密度非依存ピクセル)Google(Android)160dpiの画面(基準の密度)の1ピクセルにほぼ等しい密度に合わせてAndroidが実際のピクセル数に換算するAndroid Developers ― Use density-independent pixels ↗
px(CSSピクセル)W3C(Web)参照ピクセル(約96dpiの画面を、腕を伸ばした距離で見たときの1ピクセルの見え方)高精細な画面では、1pxが複数の実際のピクセルで描かれる(このサイトでは単に「px」と書く)CSS Values and Units ― Absolute lengths ↗

このため、44pt(Apple)・48dp(Google)・24px(W3C)は、おおよその大きさとして並べて比べられます。厳密な換算ではないので、実際に作るときは各系列の単位のまま確かめてください。NN groupは、多くの場合こうした単位の数値基準を持ちません。

用語メモ

WCAGの文字サイズ(18pt・14pt)
WCAGの「大きな文字」の18pt・14pt(太字)は印刷の単位で、Webではそれぞれおよそ24px・約18.66px。Appleの18pt(画面の論理単位)とは別の単位。
WCAGのレベル(A・AA・AAA)
達成基準ごとの適合レベル。A=最低限、AA=多くのガイドラインや調達の要件が参照する水準(求められるレベルは、地域の法律や契約などで変わる)、AAA=より高い水準。番号の先頭の数字は原則(1=知覚可能・2=操作可能・3=理解可能・4=堅牢)。
APG(ARIA Authoring Practices Guide)
W3Cが公開している、コンポーネントの作り方(キー操作やARIAの使い方)の参考例集。WCAGのような適合の基準ではない。
W3Cの参照ページのバッジ
「達成基準 A/AA/AAA」=WCAGに適合するために満たす要件とそのレベル。「参考例 APG」=実装の参考例(適合の要件ではない)。「解説 MDN」=Mozillaによる解説(W3Cの文書ではない補足)。
グレーの表記
記載なし=その系列の公式の文書に書かれていない。数値基準なし=考え方はあるが数値は決めていない。該当なし=その系列にこのコンポーネント・トピックがない。未確認=こちらで確かめられていない。

注意点・免責事項

  • このサイトは各公式ガイドラインの非公式な要約・比較です。実装や審査の最終判断には、必ず公式ページ(リンク先)の一次情報を確認してください。
  • 「AI解釈」は統合的な見解であり、特定のプロジェクトの制約(ブランドガイドライン、対象ユーザーなど)を考慮したものではありません。
  • 公式ページの内容は更新されることがあります。掲載内容と最新の公式情報が食い違う場合は、公式情報を優先してください。
  • 本文は要約・言い換えのみで構成し、原文の転載は行っていません。

運用ルール

内容の更新は完全自動では行いません。著作権・正確性の観点から、必ず人の承認を挟みます。

  1. 年1回程度、各ページのデータと公式URLを再確認する(M3 Expressiveのような大きな更新の発表があったときは、臨時に確認する)
  2. 変更点があれば、その項目だけ書き換えを提案する(変更箇所を明示)
  3. GitHubの修正用ブランチで直し、プレビューで目視確認する
  4. 「確認しました」と明示的な返答があってから、本番(GitHub Pages)に反映する

この更新作業では、レイアウトやコンポーネント構造は変更せず、数値・文章などデータ部分のみを対象とします。
