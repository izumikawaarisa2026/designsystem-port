# デザインシステム比較サイト ― プロジェクト指示書

**サイト名(仮称): DesignSystem Port**

このファイルは、Claude Codeがこのプロジェクトのフォルダで作業を始めるときに最初に読むための資料です。
ファイル名を `CLAUDE.md` にしてプロジェクトのフォルダの一番上(直下)に置いておくと、Claude Codeが毎回のセッション開始時に自動で読み込みます。そのたびに背景を説明し直す必要がなくなります。

---

## 1. 狙い・思想

### コンセプト
Apple(Human Interface Guidelines)/ Google(Material Design 3)/ W3C(WCAG)/ Nielsen Norman Group という、UI/UXの主要な考え方・ガイドラインを横断的にまとめ、AIが独自の解釈(総合するとこうだが、実務上はこう)を加えて比較できるサイトを作る。

単なる情報の転載サイトではなく、「1つのコンポーネントについて、各系列がどう違う数値・思想を持っているか」を一目で比較でき、かつそこにAIの統合見解が乗っている、という点が価値の核。

### 著作権への配慮(重要・絶対条件)
- 各公式サイトの文章をそのまま転載しない。要約・独自解釈・言い換えのみ
- 数値(タップ領域の44ptなど)は事実情報として引用可能だが、説明文はすべて言い換える
- 各項目には必ず公式ページへのリンクを添え、原文はリンク先で読んでもらう形にする

### 「放置される静的ページ」にしない
一度作って終わりではなく、内容を定期的に見直し、最新の一次情報と齟齬がないか確認し続けることを前提とする(詳細は次項)。

## 2. 作成プロセスと全体の指示

### サイト構造(3階層 + 自動生成の横断ビュー)

1. **思想レイヤー**(2ページ) ― 各系列の根本原則そのものの比較(HIGの3本柱、Materialの原則、WCAGのPOUR、NNの10ヒューリスティックなど)
2. **トークン/ファウンデーションレイヤー**(15ページ) ― 個別コンポーネントではなく、あらゆるコンポーネントに横断的に効いてくる基礎ルール。サイドバーでは「トークン / ファウンデーション」(カラー、タイポグラフィ、文章・UXライティング、アイコン、レイアウト、シェイプ、エレベーション、ダークモード、アダプティブデザインなど)と、「トークン / インタラクション」(操作と反応: インタラクション状態、モーション、サウンド、入力方法、キーボードナビゲーション)の2グループに分ける
3. **コンポーネントレイヤー**(44ページ) ― 個別UI部品ごとの比較。Material Designの伝統的な6分類(Actions / Selection / Text inputs / Navigation / Containment / Communication)に準拠して分類する
4. **横断ビュー**(1ページ・自動生成) ― 各ページに付けた原則タグ・プロセスタグから逆引きで一覧を生成する「タグから見る」ページ(エラー処理・段階的に見せるなど、UXプロセス単位の横断表示)

全体で合計62ページ(トップページを含めると63ページ、2026-10-05時点)。詳細な内訳・ページ名の一覧は `sitemap.md` を参照。

### 運用・更新プロセス(完全自動化はしない)
- 一次情報の変更は、完全自動でサイトに反映しない。必ず人の承認を挟む
- 想定サイクル: 年1回程度、Claude Codeが各ページのデータと公式URLを再確認 →変更点があればその項目だけ書き換えを提案(赤字などで変更箇所を明示) → プレビュー環境(GitHubの修正用ブランチ、またはClaudeのアーティファクトのプレビュー)でユーザーが目視確認 → ユーザーが明示的に「確認しました」と返す → 本番反映
- この更新作業では、レイアウトやコンポーネント構造(JSXやスタイル定義)は変更しない。数値・文章などデータ部分のみを更新対象とする

### ページ制作の進め方
- 全ページを一気に作らず、最初は3〜4ページの小さいバッチで作成し、レビューの負荷感を確認してから量を増やす
- 各公式URLは記憶だけで作らず、必ずWeb検索・ページ取得で実在することと内容を確認してから使う。アンカーリンクも同様に、推測せず実際にページ内に該当の見出しIDがあるか確認できたものだけ使う
- 数値や基準が実際に不明な系列(例: Nielsen Norman Groupが数値基準を明言していない項目)は、無理に数値を作らず「数値基準ではなく原則としての言及」であることを明記する

## 3. 各ページを作成するにあたっての指示

### 1コンポーネントページのデータモデル(4系列共通)

各系列(Apple / Google / W3C / Nielsen Norman Group)ごとに、以下の情報を持たせる。

| 項目 | 内容 |
|---|---|
| 基準値 | 数値+単位(例: 44 × 44 pt) |
| 基本方針(stance) | その基準を定めている理由・考え方(要約・言い換え) |
| 例外・許容ケース | 条件付きで緩和される基準がある場合はその内容(例: WCAGの4つの適合ルート) |
| 許容レンジのビジュアル | 0〜60(px相当)を共通スケールとした、非推奨(赤)/条件付き(黄)/推奨(緑)の帯とマーカーによる図 |
| アクセシビリティ(WCAG基準) | WCAGのPOUR(知覚可能・操作可能・理解可能・堅牢)のどれに対応する項目かを、略さず丁寧な文章で説明。NN groupのみ「適合区分ではなく設計上の根拠」である旨を明記 |
| 公式リンク | その系列の該当トピックの公式ページの実在URL。ページ内にその項目を扱うセクションの見出しがあり、アンカー(URL末尾の `#見出しID` )が使える場合は、ページ全体ではなくその項目の該当箇所に直接ジャンプするアンカー付きURLにする。アンカーの有無はサイトの実装(静的なHTMLか、JS描画のSPAか)によって系列ごとに異なるため、ページを取得してheadingのid等を確認し、実際に存在するもののみ使う。アンカーが取得できない場合は、その系列で見つかる最小単位のページURLに留める(存在しないアンカーを推測で作らない) |
| ページ内検索ヒント | アンカーが使えない場合の代替手段。ページ取得時に見つかった、その項目に関する実際の見出し・キーフレーズ(2〜3単語程度)を「ページ内検索: "◯◯"」として添える。ユーザーがブラウザのページ内検索(Cmd+F / Ctrl+F)でその語を打てば該当箇所にすぐ辿り着けるようにする。存在を確認していない語や推測のフレーズは使わない |

### ページ全体の構成順序
1. パンくず(コンポーネント名 / テーマ名)+ Spec番号
2. タイトル・サブタイトル
3. **AI解釈(まず結論)** ― 各系列の数値・思想の違いを統合した見解。複数の短い段落に分け、結論となる部分は太字で強調する。日本語として自然に読める段落分けにする
4. **四サイト比較図** ― 実寸に近い縮尺で4系列の基準を重ねたビジュアル。図にはタイトルを明記する
5. 各系列の詳細比較(データモデルの内容)
6. タグ(原則タグ・プロセスタグ、横断ビュー生成用)
   - 原則タグはWCAGのPOUR(知覚可能・操作可能・理解可能・堅牢)から、そのページの本文で扱っているものだけを付ける
   - プロセスタグは、横断ビュー(cross-view.jsx)の `CATEGORIES` にある12のくくりから1〜3個選ぶ(独自のタグは作らない。2026-10-04に26種類から13のくくりへ整理し、同日、作業・場面の軸にそろえて12のくくりへ組み直し)
7. フッター(最終確認日、更新方針の注記)

### 視覚化の方針
「四サイト比較図」のような固定の比較図に限らず、文章より図・グラフ・表にした方が理解しやすい情報が出てきた場合は、そのつど適切な形で視覚化する(例: 数値の推移や範囲は図、複数条件の分岐はフローチャート、状態の一覧は表など)。無理に既存のフォーマットに押し込めず、その項目の内容に合った見せ方を都度判断してよい。

### デザイン仕様

共通フォント: 日本語本文=Noto Sans JP / 英字本文・見出し=Jost / 数値・データ=IBM Plex Mono / サイトロゴ「DesignSystem Port」専用=Unbounded(600)。日本語部分はJostがCJKグリフを持たないため自動でNoto Sans JPにフォールバックする(`fontFamily: "'Jost', 'Noto Sans JP', sans-serif"`)。ロゴフォントのUnboundedは、サイトの名称そのものを表示する箇所(サイドバーのホームリンク、インデックスページのh1)にのみ使い、通常の見出しには使わない。技術仕様書(スペックシート)のような硬質な雰囲気を基調とする。

### カラーパレット(青みがかったニュートラル基調)
サイトロゴ(インディゴ #3730A3 → ビビッドブルー #2F6FED の斜めグラデーション)とサイドバー背景(#F3F6FA)を基準に、本文のテキストカラー(いわゆるグレー)も無彩色ではなく青みがかったトーンに統一している。新しくページを作る際は以下のスケールを流用すること。

| 用途 | 色 |
|---|---|
| 見出し・本文の最も濃い文字(旧: 黒に近いネイビー) | #171B36 |
| 本文・説明文 | #2E3457 |
| やや薄い本文・キャプション | #454C78 |
| メタ情報・ラベル | #565D8A |
| 控えめなメタ情報・注記 | #7E86AC |
| プレースホルダー・薄い注記 | #9EA4C4 / #A6ACC9 / #B7BCDA(文脈により使い分け) |
| ボーダー(標準) | #E1E3F0 |
| パネル背景(白よりわずかに沈める) | #F8F9FD |
| サイドバー背景 | #F3F6FA |
| アクセントブルー(リンク・サイドバーのアクティブ項目など) | #3A4FCF(ロゴのグラデーション上の色に統一) |
| AI解釈のバー・ラベル文字(あえて青系にしない) | #5A9629(フレッシュな若草色)+ 背景 #FAFCEE(ごく薄い黄緑)。リンクの青と紛れないよう意図的に別の色相を採用 |

なお、4系列を色分けする用途(四サイト比較図など)は以下の4色を使う。以前のApple(青系)がサイトのテーマカラー(インディゴ〜ブルー)と近く紛らわしかったため、暖色のオレンジに変更し、他3色も重ならないよう調整した。

| 系列 | 色 |
|---|---|
| Apple(HIG) | #C2542A(赤みのオレンジ) |
| Google(Material) | #2F7D6E(ティールグリーン、変更なし) |
| W3C(WCAG) | #A3821F(マスタードゴールド) |
| Nielsen Norman Group | #7A4F7E(プラム・マゼンタ寄りの紫、旧#6B5B95から変更) |

許容レンジ図の推奨/条件付き/非推奨を示す信号色(赤・黄・緑)は、上記の4系列識別色とは別の「意味を持つ色」なので変更しない。
アクセントカラーは鮮やかな青(#1C6FE0)ではなく、落ち着いたグレーッシュブルー(#3C5A73)を使う(AI解釈のバー・リンク文字色など)。

**スマホ版**(`design-system-compare-prototype.jsx` を型として踏襲)
- 背景は薄いブルーグレー(#EDF1F5)の紙面、コーナーに技術図面風のブラケット装飾
- 各系列の情報はカードを縦に積み上げる形で表示
- 各系列ごとに識別用の色を使う(例: HIG=青系、Material=緑系、WCAG=アンバー系、NN=紫系)
- AI解釈ボックスは各系列の詳細カードより前(上)に配置

**PC版**(`design-system-compare-desktop-matrix.jsx` を型として踏襲)
- 背景は白ベース
- マトリクス表(項目を行、4系列を列)で横並び比較。表の直上に「(コンポーネント名)デザインシステム比較」のようなタイトルを明記
- マトリクス表内では各系列を色分け・アイコンで区別せず、名前とドキュメント名のテキストのみで表示する
- ただし「四サイト比較図」(実寸オーバーレイ図)の中だけは、読みやすさのため各系列の色分けを残す。図はAI解釈ボックスと同程度のコンパクトな高さに収め、凡例文字のサイズは本文の他のテキストと揃える
- AI解釈ボックスは、かなり薄いブルーグレー背景(例: #F4F9FD)+鮮やかなブルー(例: #1C6FE0)の左バー、箱全体の枠線はなし。ラベル「AI解釈 ― まず結論」は本文より大きい見出し扱いのフォントサイズにする

### サイト共通のナビゲーション構造
- 全ページ共通の左サイドバー(`sidebar-nav.jsx`)を設置する。中身は `sitemap.md` の階層(思想レイヤー/トークン・ファウンデーションレイヤー/コンポーネントレイヤーの6分類/横断ビュー)をそのまま折りたたみ可能なグループとして表示し、現在のページをハイライトする
- サイドバーの背景は薄いブルーグレー(#F3F6FA)にし、白背景の本文エリアと視覚的に区別する。装飾は最小限にする(枠線・全角モノスペース見出し・バッジ類は使わない、余白と柔らかい角丸のみで階層を表現する、というミニマムな方向性)
- サイドバー内のアクティブページの文字色は #2C5578(本文側のアクセントブルー #3C5A73よりわずかに濃いブルー)を使う
- グループ見出しに件数バッジは付けない(シンプルさを優先)
- リンク可能(作成済み)な項目と、まだ作成していない項目は見た目で明確に区別する。作成済みは通常のリンク(クリック可能、濃い文字色)、未作成はクリックできないテキスト(薄い文字色+「準備中」タグ)にする。作成済みか未作成かをリンクの見た目だけで判断できるようにする
- 全ページを常に展開表示すると縦に長くなりすぎるため、グループ(思想レイヤー/トークン/コンポーネントの6分類/横断ビュー)ごとにアコーディオン(折りたたみ)にする。現在閲覧中のページを含むグループだけ初期状態で開き、他は閉じておく。グループの見出しには件数を付けない(上の「件数バッジは付けない」に合わせる。2026-10-05に記述の食い違いを修正)
- 幅860px未満(スマホ相当)では、常時表示の260px幅サイドバーではなくハンバーガーメニューから開くドロワーに切り替える(`sidebar-nav.jsx` の中でCSSメディアクエリにより自動切り替え済み)
- 各ページはこのサイドバーコンポーネントを `import SidebarNav from "./sidebar-nav"` で読み込み、`<SidebarNav currentPath="このページのパス" />` の形で組み込む
- サイト全体のトップには `index.jsx` をインデックスページとして置く。中身は「このサイトについて(思想)」「サイトの読み方(各要素の意味の対応表)」「対象4系列の紹介」「注意点・免責事項」「運用ルール」「更新履歴」の6セクション。公開ページの更新履歴はサイトリリース後の運用分(年次更新など)から記載する。リリース前の制作・改訂の記録は `dev-changelog.md` に追記していく(2026-09、ユーザーの指示で方針変更)
